# 第 6 章：虚拟文件系统与网络

在现代数字化工作流中，文件管理早已超越了单块物理硬盘的边界。软件工程师需要通过 SFTP 维护云端测试与生产集群；系统管理员要管理基于 SMB/CIFS 的局域网企业共享存储；创作者常常借助 WebDAV 存取私有云 NAS 和媒体资源；而极客与技术人员更是每天都要在本地检视、修改并打包动辄数以 GB 计的各类压缩包。

传统桌面操作系统往往强迫用户在割裂的应用之间来回切换：打开专门的解压工具将 ZIP 解包到临时目录，改完后再重新打包；打开第三方 FTP/SFTP 客户端上传文件；或者通过操作系统挂载弹窗把远程网络盘散乱堆放在互不相通的访达 (Finder) 窗口中。

ATBCmder 通过其强大的 **虚拟文件系统 (Virtual File System, 简称 VFS)** 引擎彻底消除了这种割裂。基于统一的 `vfs://` URI 抽象层，ATBCmder 将远程服务器和压缩包一视同仁地视为标准文件夹。您可以直接回车进入 `.tar.gz` 压缩包，按 `F3` 预览代码文件，按 `F4` 原地编辑深层配置文件（并在保存时**自动无感重新打包回写**），甚至直接在两个面板之间按下 `F5`，把文件从加密 SFTP 服务器高速流式拷入内网 SMB NAS——全程无需任何手动解压或临时文件落地！

## 2. 统一的 `vfs://` URI 抽象规范

传统文件管理器往往把远程网络盘和压缩包视为次等公民，必须依赖第三方挂载工具或先全量解压到临时目录。ATBCmder 将所有文件源全部收敛至标准化、结构严谨的统一资源定位符 (URI)：

```
vfs://[协议类型]://[用户名]@[主机地址]:[端口号]/[远端绝对路径]
```

### 2.1 虚拟路径两大范式

根据不同的数据载体与应用场景，`vfs://` URI 主要呈现为两种规范格式：

1. **压缩包虚拟路径 (Archive Virtual Paths)**：
   ```
   vfs:///Users/brain/Documents/release_v1.7.zip/src/main.py
   ```
   - **外层协议头**：`vfs://` 告知底层 `FileSystemModel` 拦截物理文件系统调用。
   - **物理容器路径**：`/Users/brain/Documents/release_v1.7.zip` 精准定位本地磁盘上实际存在的归档文件。
   - **包内虚拟成员**：`src/main.py` 定位压缩包内部层级深处的虚拟目标文件。

2. **网络服务器路径 (Network Server Paths)**：
   ```
   vfs://sftp://developer@staging.internal.net:2222/var/www/html/index.php
   vfs://smb://admin@192.168.1.50/StoragePool/Backups/2026/
   vfs://webdavs://user@cloud.mycompany.com:443/remote.php/dav/files/user/
   ```
   - **协议标识符**：指定具体的传输驱动（`sftp`、`ftp`、`ftps`、`smb`、`webdav`、`webdavs`、`gdrive`）。
   - **身份验证凭据**：编码用户名与指定端口号。
   - **远端目标路径**：对应远程服务器主机上的绝对目录或文件系统路径。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              VFS 路径解析全流程示意                                    │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│   输入示例: vfs://sftp://deploy@aws.infra:22/var/log/nginx/access.log                  │
│                 │      │        │        │   └────────────────────► 远端绝对路径       │
│                 │      │        │        └────────────────────────► 端口 (默认 22)     │
│                 │      │        └─────────────────────────────────► 远程主机 / 域名    │
│                 │      └──────────────────────────────────────────► 登录用户名         │
│                 └─────────────────────────────────────────────────► 网络传输协议驱动   │
│                                                                                        │
│   输入示例: vfs:///Volumes/Data/Archive.zip/docs/manual.pdf                            │
│                 │                      │        └─────────────────► 压缩包内部文件     │
│                 │                      └──────────────────────────► 物理压缩包文件     │
│                 └─────────────────────────────────────────────────► 虚拟文件系统协议头 │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 双面板无缝协同交互

因为所有虚拟路径在 ATBCmder 内部都遵循统一的抽象目录模型，所以您能享受到完整的双面板交互能力：
- **多标签虚拟工作区**：在左侧面板标签页 1 打开远程 SFTP 服务器，标签页 2 打开本地加密 ZIP 包，标签页 3 打开本地 `~/Downloads` 目录，多源自由切换。
- **定向双向复制 (`F5`)**：在本地激活面板中选中文件并按下 `F5`，即可将其直接推送到对侧面板展示的远程服务器或压缩包内部。
- **直接拖拽传输 (Drag-and-Drop)**：跨越面板边界，在本地磁盘、网络共享以及归档内部层级之间直接拖拽文件，无需中间繁琐落地。
- **动态交互式面包屑导航条**：面包屑路径栏能够智能解析虚拟 URI 为可点击的层级按钮。点击任何父级目录或根服务器徽标，即可瞬间折跃至对应层级。

### 3.2 原地畅游的日常操作流

在压缩包内部漫游浏览时：
1. **进入子目录**：在压缩包内的任何文件夹上按下 `Enter`（回车），立即展开深层嵌套目录。
2. **返回上一级 (`..`)**：按下 **`Backspace`**（退格键 `⌫`）或双击 `.. [上一层目录]` 返回上级。到达压缩包的根目录后再按退格键，即可优雅返回包含该压缩包的外部物理文件夹。
3. **即时预览 (`F3` / `Fn+F3`)**：在包内的任何文档、图片或源码文件上按下 `F3`，ATBCmder 会在沙箱中仅流式提取该单项，并在全能查看器中毫秒级展现。
4. **按需单项提取 (`F5` / `Fn+F5`)**：不必为了取出几个小文件而解压几十 GB 的庞大压缩包。直接在包内选中需要的文件并按下 `F5`，ATBCmder 会单独将选中的条目解压并投递到对侧面板中。

> [!NOTE]
> 在压缩包内预览或复制单个文件时，ATBCmder 只从容器流中按需提取目标字节块，绝不会把未选中的同级文件也解压出来，既节省了磁盘空间，又大幅提升了响应速度。

## 4. 实时重打包 (Live Repacking)：在压缩包内原地编辑

ATBCmder 最受极客欢迎的核心功能之一就是 **实时重打包 (Live Repacking)**。在传统工作流中，修改压缩包内的一个配置文件需要极度繁琐的六个步骤：解压整个包 ➔ 找到目标文件 ➔ 编辑并保存 ➔ 重新压缩为同名文件 ➔ 删除原压缩包 ➔ 清理临时解压目录。

ATBCmder 让修改压缩包内的文件变得像修改本地普通文件一样直观自然。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              实时重打包 (LIVE REPACKING) 生命周期                      │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│  1. 用户在 "package.zip" 内部对 "config.json" 按下 F4 编辑                             │
│     │                                                                                  │
│     ├──► ATBCmder 提取 "config.json" 到沙箱: /tmp/dc_repack_xyz/config.json            │
│     └──► 唤起内置 EditorDialog，窗口标题显示: "config.json — Editor"                   │
│                                                                                        │
│  2. 用户在编辑器中修改配置并按下 Cmd+S (保存)                                          │
│     │                                                                                  │
│     ├──► 编辑器发出 file_saved 信号                                                    │
│     └──► RepackWorker 后台线程比对原压缩包体积与 ArchiveRepackWarningMB 安全阈值       │
│                                                                                        │
│  3. 原子级重打包执行 (Atomic Repack)                                                   │
│     │                                                                                  │
│     ├──► 将修改后的流式数据写入暂存归档: /tmp/package.zip.tmp                          │
│     ├──► 校验新生成容器的完整性与内部签名                                              │
│     ├──► 执行原子替换: os.replace("/tmp/package.zip.tmp", "/original/package.zip")      │
│     └──► 自动刷新当前激活面板，并彻底清理临时沙箱 /tmp/dc_repack_xyz/                  │
│                                                                                        │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 分步实操：修改压缩包内的配置文件

1. 按 `Enter` 回车进入压缩包（如 `application_bundle.zip`）。
2. 定位到需要调整的配置文件（如 `settings.yaml`）。
3. 按下 **`F4`**（或 `Fn+F4`）。ATBCmder 会自动将该文件提取到沙箱缓存中，并调出内置全功能代码编辑器。
4. 在编辑器中按需修改内容。
5. 按下 **`Cmd+S`**（`⌘S`）保存文件。
6. 按 `Cmd+W` 或 `Esc` 关闭编辑器。
7. ATBCmder 的 **`RepackWorker`** 守护进程会自动捕获变更，在后台将更新后的文件重新打包装入原归档，执行原子替换，并实时刷新文件列表。

> [!CAUTION]
> **超大归档安全预警阈值 (`ArchiveRepackWarningMB`)**  
> 对压缩归档进行局部重打包，底层通常需要重新解压并重新编码整个容器的数据流。如果您在一个 20GB 的 `.tar.gz` 蓝光视频压缩包里修改一个 10KB 的文本文件，系统将不得不重写整整 20GB 的数据！  
> 
> 为防止因误操作导致磁盘长时间高负荷运转，ATBCmder 设置了安全防线（`ArchiveRepackWarningMB`，在 `atbcmder.xml` 中默认为 **100 MB**）。当您试图在超过此阈值的超大压缩包内编辑或删除文件时，系统会弹出明确的警示确认弹窗：  
> *"修改此归档需要对整个压缩包重新打包，这可能需要较长时间。是否确认继续？"*

## 5. 创建与提取压缩包 (`Alt+F5` / `Alt+F9`)

ATBCmder 为归档的创建与提取配置了独立的后台工作线程，确保在执行耗时数分钟的大体积压缩任务时，双面板界面依然流畅可用、绝不假死卡顿。

![压缩与解压缩参数设置](images/archive_pack_extract.png)  
*图 6.2：压缩打包对话框 (Alt+F5 / cm_PackFiles)，支持目标路径定制、格式切换、压缩级别调优与 AES-256 密码加密。*

### 5.1 压缩打包文件 (`Alt+F5` / `⌥F5` / `cm_PackFiles`)

创建新归档只需以下几步：
1. 在当前激活面板中，选中一个或多个需要打包的文件或文件夹。
2. 按下 **`Alt+F5`**（`⌥F5`），或从顶部菜单栏选择 **文件 ➔ 打包压缩...**。
3. 弹出 **打包压缩** 对话框：
   - **目标归档路径**：生成归档的存储路径。默认自动指向对侧闲置面板所在的目录，并以当前焦点条目命名。
   - **归档格式**：自由选择 `ZIP`、`TAR`、`TAR.GZ`、`TAR.BZ2`、`TAR.XZ` 或 `7Z`。
   - **压缩级别**：
     - `存储 (Store)`：仅打包不压缩；适合用于本身已高度压缩的媒体文件（MP4、JPEG、MKV）。
     - `极速 (Fast)`：CPU 占用极低，优先保证打包速度。
     - `标准 (Normal Deflated)`：兼顾压缩比与运行性能（日常通用推荐配置）。
     - `最大 (Maximum)`：极限压缩模式（在支持的格式下启用 LZMA/Bzip2 极限算法）。
   - **保护密码 (仅限 ZIP)**：输入加密口令，对归档内的文件进行加密保护。
4. 点击 **确定**（或回车）。压缩任务将在非阻塞的后台线程中平稳运行，同时呈现精确的进度条与逐文件处理状态。

#### 工业级 AES-256 密码加密防护
传统的 ZIP 加密方式（老旧的 ZipCrypto）在密码学上已被证实极易被破解，存在严重的明文已知字典攻击漏洞。在 ATBCmder 中为 ZIP 压缩包设置密码时，系统原生采用基于 `pyzipper` 的 **AES-256 工业级高强度加密**（遵循 `WZ_AES` 国际标准）。该标准不仅完全兼容 macOS 原生解压机制、WinZip 与 7-Zip，还能有效阻断暴力破解与中间人刺探。

#### 超大文件跨介质分卷压缩与合并
若您需要通过邮件附件发送大文件，或将大体积素材分发到受 FAT32 单文件 4GB 限制的 U 盘与云存储：
1. 先使用 `Alt+F5` (`cm_PackFiles`) 将文件完整打包。
2. 光标停留在生成的 `.zip` 或 `.tar` 文件上，按下 **`Alt+F6`** 唤起文件分割器 (`cm_FileSpliter`)。
3. 选择预设分卷大小（如 `100 MB`、`4.7 GB DVD`、`CD 700 MB`，或输入自定义字节大小）。
4. ATBCmder 会批量生成带序列编号的分卷切片（如 `archive.zip.001`、`archive.zip.002` 等）并附带 CRC32 校验清单。接收方在任何电脑上随时可以通过 **`cm_FileLinker`**（文件合并器）将其无损复原。

### 5.2 解压提取归档 (`Alt+F9` / `⌥F9` / `cm_ExtractFiles`)

将压缩包批量解压落地到磁盘中：
1. 在激活面板中选中一个或多个压缩包文件。
2. 按下 **`Alt+F9`**（`⌥F9`），或从顶部菜单栏选择 **文件 ➔ 解压...**。
3. 弹出 **解压文件** 对话框：
   - **待解压文件**：显示当前选中的归档路径。
   - **解压目标路径**：解压落地目录（默认自动对齐对侧闲置面板的当前路径）。
   - **包内预览列表**：支持在弹窗内动态检视压缩包内部的文件清单。
   - **解压密码**：针对受密码保护的归档输入解密口令。
4. 点击 **确定**。解压过程中若遇到目标目录已有同名文件，ATBCmder 会主动暂停并弹出交互式冲突处理窗口：
   - **覆盖**：替换当前冲突的单个目标文件。
   - **跳过**：保留现有目标文件不动，继续解压下一个条目。
   - **全部覆盖**：后续所有重名文件全部静默覆盖。
   - **全部跳过**：后续所有重名文件全部自动跳过。
   - **取消**：安全中止解压任务，保留已解压好的部分。

### 6.2 协议深度解析与专属特性

#### SFTP (SSH 文件传输协议)
基于业界标杆级 `paramiko` SSH 核心引擎，ATBCmder 的 SFTP 驱动在端口 22 上建立加密隧道：
- **主机指纹安全防护 (`WarningPolicy`)**：严格遵循安全准则，ATBCmder 会自动调阅本地 `~/.ssh/known_hosts`。连接已知主机时自动校验公钥指纹；遇到未知服务器时，系统会弹出明确的安全告警，绝不静默信任来历不明的公钥。
- **SSH 私钥免密登录**：除了传统密码登录外，完全支持加载本地 SSH 私钥（如 `~/.ssh/id_rsa`、`~/.ssh/id_ed25519`）。
- **UNIX 文件属性无损映射**：完整保留远程文件的八进制文件权限模式 (`chmod`)、所属用户/用户组属性以及精确的 POSIX 修改时间戳。

#### FTP 与 FTPS (明文 / TLS 加密传输)
基于 Python 内置 `ftplib` 深度重构的 FTP 驱动支持：
- **被动传输模式 (PASV)**：默认强制开启被动模式，确保在穿透复杂 NAT 家用路由器与企业级防火墙时依然保持稳定通信。
- **多语言编码自适应切换**：彻底告别跨平台中文乱码！支持在 `UTF-8`、`ISO-8859-1`、`GB18030` 与 `Windows-1252` 字符编码之间一键切换。

#### SMB / Samba (Windows 局域网共享与 NAS 设备)
不同于传统的慢速纯用户态 Python SMB 库，ATBCmder 采用了混合加速架构：
- **macOS 原生内核级硬件加速 (`mount_smbfs`)**：在 macOS 上，ATBCmder 的 `SambaMounter` 深度联动系统底层的 `/sbin/mount_smbfs`。它将远程网络共享直接挂载进 macOS 原生 VFS 树（`/Volumes/` 或隔离挂载点），释放出纯原生硬件加速的 SMB3 极致吞吐带宽。
- **现存挂载点智能感知**：若 macOS 访达或系统开机脚本已经挂载了目标 SMB 卷，ATBCmder 会自动从系统的 `mount` 挂载表中嗅探并瞬间定位进入，避免重复建立冗余连接。

> [!IMPORTANT]
> **SMB 共享名称必填规则**  
> SMB 协议规范不允许直接在裸主机名层级浏览。因此，SMB 的 URI **必须**在路径末尾指定具体的共享文件夹名称：  
> - ❌ 错误示例：`vfs://smb://nas.local/`  
> - ✅ 正确示例：`vfs://smb://nas.local/StoragePool` 或 `vfs://smb://192.168.1.100/Media`

#### WebDAV 与 WebDAVS (Nextcloud 私有云与云存储)
基于 `webdavclient3` 驱动，提供与现代私有云存储的双向同步通道：
- **SSL 证书校验模式**：对公网 WebDAVS 服务执行严苛的 SSL 证书链验证；针对家庭自建的局域网自签名证书服务，提供一键信任跳过开关。
- **递归深层目录创建 (`makedirs`)**：在批量上传文件时，若远端不存在父级多层目录，驱动会自动执行递归建构，防止批量上传失败。

## 7. 快速连接 vs 连接管理器

ATBCmder 为连接远程主机提供了两套相辅相成的方案：针对临时调试的 **快速连接**，以及面向固定服务器资产的 **连接管理器**。

### 7.1 快速临时连接 (`cm_NetworkConnect`)

当您需要临时连入某台设备处理突发问题，不想把配置持久保存污染书签时：
1. 选择菜单栏 **网络 ➔ 快速连接...**（或运行命令 `cm_NetworkConnect`）。
2. 弹出精简轻快的快速拨号弹窗：
   - **协议**：选择 `sftp`、`ftp`、`ftps`、`smb`、`webdav`、`webdavs` 或 `gdrive`。
   - **服务器地址与端口**：输入主机 IP 或域名（端口随协议自动回填默认值）。
   - **用户名与密码**：输入远端认证信息。
   - **远程起始路径**：指定登入后的初始目录（默认为 `/`）。
   - **记住密码**：临时连接建议保持不勾选。
3. 点击 **测试连接**，在正式载入前先行验证网络握手与身份认证是否通畅。
4. 点击 **连接**。ATBCmder 会立即在当前面板新建一个标签页，直连远端服务器。

## 8. 凭据安全与 macOS 钥匙串原生集成

在各类针对开发者的网络安全攻击中，文件管理器的配置文件往往是重灾区。许多传统文件管理工具把 FTP/SFTP 密码明文存放在用户家目录的 XML 或 INI 文本中，极易被恶意扫描脚本盗取。

**ATBCmder 承诺：绝不在磁盘配置文件中以任何明文形式存储敏感凭据！**

### 8.1 凭据安全存储架构

```

│                           凭据多层安全存储体系架构                                     │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│   持久化配置 XML 文本                           macOS 系统原生安全钥匙串               │
│   (~/.config/atbcmder/atbcmder.xml)            (服务标识: "ATBCmder_VFS")              │
│   ┌─────────────────────────────────────┐      ┌─────────────────────────────────────┐ │
│   │ <connection>                        │      │ 标识: "AWS 生产集群跳板机"          │ │
│   │   <label>AWS 生产集群跳板机</label> │      │ 密文: 硬件安全区高强度加密口令      │ │
│   │   <scheme>sftp</scheme>             │      │ 访问: 受 Apple 安全芯片硬件隔离守护 │ │
│   │   <host>aws.infra.net</host>        │      └─────────────────────────────────────┘ │

│   │ </connection>                       │                         │                    │
│   └─────────────────────────────────────┘                         │                    │
│         ▲                                                         │                    │
│         │ 保存时强制剔除密码置空                                   │ 经由系统           │
│         └─────────────────── ConnectionManager ───────────────────┘ keyring 安全存入   │
│                                                                                        │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

1. **XML 配置文件明文脱敏**：无论在任何时候将连接配置序列化落盘到 `atbcmder.xml`，`ConnectionManager.save()` 方法均会在执行前强制执行 `d["password"] = ""` 置空。即便配置文件被意外读取或泄漏，也不会暴露任何服务器密码。
2. **Apple 原生 Keychain 硬件加密**：若勾选了 **记住密码**，系统会调用 Python `keyring` 模块直接把密码存入 macOS 钥匙串，服务名为 `ATBCmder_VFS`。密钥派生与数据加解密全程受 Apple 芯片硬件 Secure Enclave 保护。
3. **动态会话内存保护**：若未勾选“记住密码”，凭据仅保存在当前运行期的动态内存结构（`VFSSessionCache`）中，在退出 ATBCmder 的瞬间即被彻底抹除。

## 9. ⚡ 高手进阶：高性能远程与归档实战技巧

### 技巧 1：非阻塞后台传输队列 (`cm_OperationsPanel`)
当跨越远程服务器拷贝海量目录，或通过 SFTP 下载数十 GB 的系统镜像时，切勿让界面冻结。ATBCmder 的所有网络与归档操作均原生接入 **后台任务队列系统**：
- 按 **`F5`** 启动传输时，可直接点击 **后台** 按钮将任务派入队列。
- 通过菜单栏 **显示 ➔ 后台任务面板**（`cm_OperationsPanel`）随时调出监视窗口，查看实时传输速率曲线、逐文件进度与剩余时间估算。
- 您可以随时对任务进行暂停、继续或调整先后次序，期间完全不影响双面板对本地文件的正常浏览与操作。

### 技巧 2：异构协议间的点对点流式直传
ATBCmder 内置的 `stream_copy_file` 引擎支持**跨协议直接管道流式传输**。例如将左侧面板 SFTP 服务器上的大文件夹直接拖拽到右侧面板的内网 SMB 共享盘中：
- ATBCmder **不会**先将庞大的目录全量下载到本地 Mac 固态硬盘，再重新上传到 SMB。
- 系统在内存中构建环形缓冲区，将源端 Socket 读取到的数据块直接管道写入目标端 Socket。不仅减少了对本地 SSD 寿命的磨损，而且即使 Mac 本地磁盘可用空间不足，也能从容完成远端之间海量数据的无缝迁移！

### 技巧 3：网络长连接保活与自动重连机制
复杂的企业级硬件防火墙或家庭 NAT 路由常会在闲置 60 到 300 秒后强制切断空闲 TCP 连接。为避免在浏览深层远程树形目录时连接断开：
- ATBCmder 的 `BaseNetworkVFS` 基类会自动在空闲时段向远端发送轻量级心跳探针包，维持会话活性。
- 若遭遇偶发性网络抖动，内部的 `_retry()` 故障恢复机制会自动执行最多 **3 次重试**，采用平滑的指数退避策略（每次间隔 `2^attempt` 秒），确保在弱网环境下依然坚如磐石。

### 技巧 4：远程代码文件的编辑与自动回传流水线
需要直接修改远端 Linux 服务器上的 `nginx.conf` 或 Python 脚本？
1. 在 SFTP 或 WebDAV 面板中选中目标远程文件。
2. 按下 **`F4`**（`Fn+F4`）。
3. ATBCmder 会将该文件快速拉取到隔离临时沙箱（`/tmp/`）并在内置编辑器中打开。
4. 每次按下 **`Cmd+S`**（`⌘S`）保存时，系统都会触发 `_upload_vfs_temp()` 异步将修改后的文件推回远程服务器，并在状态栏轻量提示上传成功。
5. 关闭编辑器后，本地临时沙箱文件会被安全擦除。

## 10. 系统权限与安全警示

> [!WARNING]
> **SSH 主机指纹变更警报 (Host Key Verification Mismatch)**  
> 如果目标 SFTP 服务器重装了操作系统重新生成了密钥，或者当前局域网存在中间人欺骗攻击，ATBCmder 会检测到远程公钥指纹与本地 `~/.ssh/known_hosts` 不符。  
> 在公共 Wi-Fi 环境下遇到此类告警，切勿盲目跳过，请务必先与服务器管理员独立核对公钥指纹！

> [!IMPORTANT]
> **超大远程文件预览的临时空间注意**  
> 当在远程 VFS 服务器上按 `F3` 预览或按 `F4` 编辑大体积文件时，ATBCmder 会将数据暂存至系统的 `/tmp` 目录。在打开数 GB 级别的大型音视频或数据库文件前，请确保 Mac 的 APFS 启动盘留有足够的临时写入空间。

> [!CAUTION]
> **正确卸载与断开网络共享**  
> 对于通过 macOS `mount_smbfs` 挂载的局域网 SMB 共享，如果在未安全断开的情况下直接拔掉网线或合上电脑，可能会在系统的 `/Volumes/` 目录下残留无效的假死挂载点。合盖或切换网络前，请优先在面板驱动器菜单中点击断开连接。
