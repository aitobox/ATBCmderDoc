# 第7章：システムツールとメンテナンス

プロフェッショナルなファイル マネージャーは、単独で動作するのではなく、ストレージ、メモリ、オペレーティング システム リソースの中枢です。 従来のデュアルパネル ファイル管理はディレクトリ階層の整理、移動、同期に優れていますが、パワー ユーザー、開発者、システム管理者はシステム レベルの課題に頻繁に直面します。つまり、どの隠しディレクトリが 50 GB のディスク領域を静かに消費しているかを特定し、CPU コアをスラッシングしている暴走バックグラウンド プロセスを特定し、放棄された開発者キャッシュとビルド アーティファクトのギガバイトをクリアし、孤立した環境設定ファイルを残さずに従来の macOS アプリケーションを完全にアンインストールする必要があります。 デーモン、または `~/Library/` 全体に散在するアプリケーション サポート フォルダー。 

ATBCmder は、4 つの特殊なシステム メンテナンスおよび診断ツールを **ツール** メニューに直接統合します。 非同期ネイティブ監視デーモンを活用したこれらのツールは、ユーザー インターフェイスをロックしたり、大量の広告を満載したサードパーティ ユーティリティ アプリケーションを必要としたりすることなく、ファイル パネルと並行してシームレスに動作します。

### 2.1 カプセルのコンポーネントとビジュアルスタイリング

ステータス カプセル (`320px` 幅) には、1 秒ごとに更新される 3 つのリアルタイム テレメトリ メトリックが表示されます。 

1. **CPU 使用率**: 動的色分けによるライブ集計プロセッサ使用率:
 - **通常 (< 75%)**: Accent blue / theme foreground.
   - **Elevated (75% – 90%)**: Warning orange.
   - **Critical (> 90%)**: 赤色の警告。 
2. **メモリ使用率 (RAM)**: 現在のアクティブな有線メモリの負荷を物理 RAM のパーセンテージで表します。 
3. **ネットワーク スループット**: コンパクトにフォーマットされたすべてのアクティブなネットワーク アダプターにわたるリアルタイムの合計アップロード速度とダウンロード速度 (例: `↓2.4 MB/s ↑512 KB/s`)。

### 2.2 インタラクティブなポップオーバー (`StatusPopup`)

ステータス カプセルの任意の場所をクリックすると、非モーダルなフローティング **ステータス ポップオーバー**が開きます。 

- **ハードウェア テレメトリ**: CPU、メモリ、GPU、バッテリーの状態 (充電率と充電状態を含む) の合計パーセンテージを表示します。 
- **ファイルシステムのマウント**: マウントされているすべてのローカル APFS コンテナーと外部ドライブを、空き領域と合計容量バーとともにリストします。 
- **上位 5 プロセス**: CPU パーセンテージとメモリ フットプリントに基づいて、リソース消費量が最も高い 5 つのプロセスを強調表示します。 
- **詳細ボタン**: **「フル システム モニターを開く」** をクリックして (または `⌘⇧M` を押して)、包括的な診断ウィンドウを起動します。

### 2.3 カプセルの可視性の設定

ファイル ナビゲーション コントロールのみを備えた、気を散らすことのないツールバーを希望する場合は、次のようにします。 

1. **環境設定** (`⌘,` / **構成 ➔ オプション...**) を開きます。 
2. 左側のサイドバーで [**全般**] を選択します。 
3. [**表示とレイアウト**] で、チェックボックスを切り替えます。 
`[X] Show system status capsule on toolbar`

 4. [**適用**] または [**OK**] をクリックします。 カプセルはメイン ツールバーにすぐに表示または非表示になります。

### 3.1 診断機能とメトリックセクション

1. **マルチコア プロセッサ モニター**:
 - 全体的なシステム負荷と個々のパフォーマンスおよび効率コアにわたる内訳を視覚化します。 
- コアごとの進行状況メーターは、マルチスレッドのコンパイルまたはレンダリング中のコアの飽和状態を強調表示します。 
2. **メモリの故障とスワップの圧力**:
 - 物理メモリの割り当てをアプリ メモリ、有線メモリ、圧縮メモリ、キャッシュ ファイルに分類します。 
- 仮想スワップの使用状況を監視して、メモリ リークがいつディスク ページングを引き起こしているかを特定します。 
3. **ストレージとマウントの概要**:
 - マウント ポイントの容量データとともに、リアルタイムのディスク読み取り/書き込みスループット メトリックを表示します。 
4. **対話型プロセス マネージャー**:
 - 実行中のすべてのシステムタスクとユーザータスクを含むリアルタイムのソート可能なテーブル。 
- **検索とフィルター**: 検索ボックスにプロセス名または PID を入力すると、結果が即座にフィルターされます。 
- **プロセスの終了**:
 - [**Kill**] をクリックするか、プロセスを選択して `Delete` を押します。 
- 正常なシャットダウンの場合は **終了 (`SIGTERM`)**、応答しないタスクの場合は **強制終了 (`SIGKILL`)** を提供する確認ダイアログが表示されます。

## 4. ディスク使用量アナライザー (`cm_DiskUsageAnalyzer` / `⌘⇧D`)

ソリッド ステート ドライブの空き容量が不足し始めると、ギガバイト単位のデータがどこに隠されているかを見つけるのが非常に遅くなることがあります。 標準の Finder ファイル リストではフォルダー サイズが自動的に計算されないため、手動で検査するにはネストされた階層をドリルダウンする退屈な作業が必要になります。 

**ディスク使用状況アナライザー** (`cm_DiskUsageAnalyzer`、ホットキー **`⌘⇧D`** / **`Ctrl+Shift+D`**) は、マルチスレッド スキャナーを使用してディレクトリ ツリー全体を非同期にスキャンし、従来の階層ツリー リストと対話型の **二乗ツリーマップ** の両方を使用してストレージを視覚化します。

### 4.1 主要なアーキテクチャと機能

- **非同期マルチスレッド スキャン**: ATBCmder のメイン インターフェイスをフリーズさせることなく、APFS コンテナ全体で数十万のファイルをスキャンします。 進行状況バーには、1 秒あたりにスキャンされたディレクトリが表示されます。 
- **正方形のツリーマップの視覚化**:
 - フォルダーとファイルは、入れ子になった長方形のブロックとして表され、その 2D 表面積はディスク上のサイズに厳密に比例します。 
- 色はディレクトリの深さを自動的に反映するため、大規模なストレージの消費者を一目ですぐに識別できます。 
- **双方向同期**:
 - ディレクトリ ツリー内の項目を選択すると、ツリーマップ内の対応するブロックが強調表示されます。 
- ツリーマップ内の任意の四角形をクリックすると、ツリー ビュー内の行が強調表示され、完全なファイル パスと正確なバイト サイズが表示されます。

### 4.2 インタラクティブなナビゲーションとワークフロー

1. **ドリルダウン**: フォルダー行またはツリーマップ ブロックをダブルクリックして、そのサブディレクトリにズームインし、新しいルートを基準にしてビューを再計算します。 
2. **ズームアウト**: ツールバーの**ズームアウト** ボタンをクリックするか、上部の階層リンクバーの任意のセグメントをクリックして、親ディレクトリに戻ります。 
3. **デュアル パネルで検査**: [**デュアル パネルで表示**] をクリックすると、アクティブな ATBCmder ファイル パネルが選択したディレクトリに即座に移動します。 
4. **インスタント クリーンアップ**: 古くなった大きなフォルダーまたはファイルを選択し、**`⌘⌫`** を押します (または **ゴミ箱に移動**をクリックします)。 アイテムは macOS のゴミ箱に安全に送信され、スキャン ツリーは自動的に更新されます。 
5. **ストレージ レポートのエクスポート**: [**エクスポート**] をクリックすると、ストレージ計画用に構造化された CSV またはプレーン テキストの概要としてフォーマットされた包括的なディスク使用量監査が生成されます。

## 5. システムクリーナー (`cm_CleanSystem` / `⌘⇧C`)

macOS は、数か月にわたる毎日の使用により、古いアプリケーション キャッシュ、Xcode ビルド アーティファクト、パッケージ マネージャーのダウンロード、孤立した診断ログ、ブラウザ キャッシュなど、ギガバイト単位の一時データが蓄積されます。 一部のキャッシュはワークフローを高速化しますが、古いアイテムは貴重な高速 SSD ストレージを無駄にします。 

**システム クリーナー** (`cm_CleanSystem`、ホットキー **`⌘⇧C`** / **`Ctrl+Shift+C`**) は、企業の安全性を保証するように設計された決定的な 2 段階のシステム クリーナーを提供します。

### 5.1 2 段階の安全アーキテクチャ

バックグラウンドでサイレントにファイルを削除する無謀な「ワンクリック クリーナー」とは異なり、ATBCmder は厳格な **2 段階の安全プロトコル**を強制します。 

1. **ステージ 1: ドライラン スキャンと評価**:
 - クリーナーは、標準化されたシステムの場所全体で読み取り専用の調査を実行します。 
- 1 バイトも変更または削除せずに、正確なファイル数とバイト サイズを計算します。 
- 結果を明確なリスク評価を備えた透明なカテゴリにグループ化します。 
2. **ステージ 2: ユーザーレビューによる選択的削除**:
 - 分類されたリストを確認し、個々の項目またはカテゴリ全体をオンまたはオフにします。 
- **「選択した項目を消去」** をクリックすると、明示的にチェックされたターゲットのみが削除されます。 
- すべての削除イベントは、`~/Library/環境設定/atbcmder/operations.log` のアトミック監査ログに書き込まれます。

### 5.2 6 つのコアクリーンアップドメイン

| カテゴリー | 一般的な場所 | リスクレベル | 説明 |
 | :--- | :--- | :---: | :--- |
 | **アプリケーション キャッシュ** | `~/Library/Caches/` | **安全** | デスクトップ アプリケーションによって生成された古いキャッシュは、必要に応じて自動的に再作成されます。 |
 | **システムとユーザーのログ** | `~/Library/Logs/`、`/var/log/` | **安全** | 古いクラッシュ ログ、診断ダンプ、ソフトウェア アップデート ログは、トラブルシューティングに必要なくなりました。 |
 | **ブラウザ キャッシュ** | Safari、Chrome、Edge、Firefox | **安全** | インストールされているデスクトップ ブラウザ全体でキャッシュされた Web ページ、メディア バッファ、およびスクリプト アーティファクト。 |
 | **Xcode 派生データ** | `~/Library/Developer/Xcode/DerivedData` | **警告** | 過去の Apple 開発者ビルドからの中間オブジェクト ファイル、モジュール キャッシュ、インデックス データ。 |
 | **パッケージ マネージャーのキャッシュ** | Homebrew、CocoaPods、NPM、糸 | **警告** | ダウンロードされた tarball、数式アーカイブ、およびパッケージ キャッシュ ディレクトリ。 |
 | **ゴミ箱** | `~/.ゴミ箱`、`.ゴミ箱es` | **危険** | 以前に macOS のゴミ箱に移動されたものの、まだ完全に空になっていないアイテム。 |

### 5.3 リスク階層と安全性ホワイトリスト

- 🟢 **安全 (緑)**: 構成の損失やワークフローの中断を伴わずに削除できる一時キャッシュと破棄されたメタデータ。 
- 🟡 **警告 (オレンジ色)**: 開発者アーティファクトまたはパッケージ キャッシュ。 削除しても安全ですが、その後のプロジェクトのコンパイルやパッケージのダウンロードでは、項目が再フェッチされるため時間がかかります。 
- 🔴 **危険 (赤)**: 明示的な確認が必要なファイルが含まれています (ゴミ箱を完全に削除するなど)。 
- **カスタム ホワイトリスト ルール**:
 - ATBCmder が **決して**触れてはならない特定のパス、拡張子、またはフォルダー名を `~/.config/atbsys/whitelist` に追加します。 
- 組み込みの保護ルールにより、重要な macOS オペレーティング システム ファイル、ユーザー キーチェーン ディレクトリ、およびクラウド ストレージのオフライン同期フォルダーのスキャンが自動的に防止されます。

## 6. アプリケーション アンインストーラー (__ ATB_INL_00000 __ / __ ATB_INL_00001 __)

macOS では、アプリケーションを `/Applications` からゴミ箱にドラッグしても、`.app` バンドル自体のみが削除されます。 最新のアプリケーションでは、設定 plist、アプリケーション サポート データベース、バックグラウンド起動エージェント、コンテナ サンドボックス、キャッシュされたメディアなど、数百もの補助ファイルがドライブ全体に散在することがよくあります。 時間の経過とともに、これらの孤立した残り物は何ギガバイトものストレージを消費し、ログイン時に不要なバックグラウンド プロセスが実行されたままになる可能性があります。 

**アプリケーション アンインストーラー** (`cm_UninstallApp`、ホットキー **`⌘⇧U`** / **`Ctrl+Shift+U`**) は、アプリケーションとそれに関連する残存物を完全に根絶するための詳細な依存関係スキャンを提供します。

### 6.1 残骸の発見場所

アプリケーション コンポーネントをスキャンするとき、ATBCmder はバンドル ID の正確な一致を使用して、次の標準 macOS サブシステムの場所を検索します。 

1. **アプリケーション バンドル**: `/Applications/<Name>.app` および `~/Applications/<Name>.app`。 
2. **アプリケーション サポート**: `~/Library/Application Support/<Name>` および `<BundleID>`。 
3. **アプリケーション キャッシュ**: `~/Library/Caches/<BundleID>`。 
4. **設定とデフォルト**: `~/Library/環境設定/<BundleID>.plist`。 
5. **保存された状態**: `~/Library/Saved Application State/<BundleID>.savedState`。 
6. **デーモンとエージェントの起動**: `~/Library/LaunchAgents/<BundleID>.plist`。 
7. **サンドボックス コンテナ**: `~/Library/Containers/<BundleID>/` および `~/Library/Group Containers/`。 
8. **アプリケーション ログ**: `~/Library/Logs/<Name>/`。

### 6.2 デュアル動作モード

- **完全なアンインストール (デフォルト)**:
 - 現在 Mac にインストールされているアプリケーションを削除することを目的としています。 
- 単一のアトミック アクションで、`/Applications` からの実行可能 `.app` バンドルと、関連するすべての補助サポート ファイルの両方を削除します。 
- **残骸のみ**:
 - Finder またはサードパーティ ツールを介して以前に手動で削除されたアプリケーションの後のクリーンアップを目的としています。 
- `~/Library/` をスキャンして、親 `.app` バンドルがシステム上に存在しない孤立したサポート フォルダーを探します。

### 6.3 Apple システムの整合性と安全性のガードレール

偶発的なシステムの不安定化を防ぐには:

 - **システム アプリの保護**: 組み込みの macOS システム アプリケーション (Safari、Finder、プレビュー、ミュージック、システム設定など) は読み取り専用のロック アイコンで保護されており、アンインストールできません。 
- **プロセス検出の実行中**: アプリケーションまたはそのヘルパー デーモンが現在アクティブな場合、ATBCmder はアンインストールを続行する前にアプリケーションを正常に終了するように求めるメッセージを表示します。 
- **ゴミ箱-First Protocol**: アンインストールされたすべてのアイテムは、ディスクからすぐにリンク解除されるのではなく、デフォルトで macOS のゴミ箱に移動されるため、必要に応じて完全に復元できます。

## 7. システムおよびメンテナンスのアラート

> [!NOTE]
 > **最小限のシステム リソース オーバーヘッド**
 > バックグラウンド ステータス モニター デーモンはネイティブ コンパイル コードで設計されており、1.0 秒のポーリング間隔で実行されます。 アクティブなファイルの閲覧中に CPU を消費するのは 0.1% 未満で、ATBCmder が最小化または非表示になっている場合はポーリングが自動的に一時停止されます。 

> [!ヒント]
 > **ディスク使用量アナライザーとデュアルパネル フラット ブランチ ビューのペアリング**
 > ディスク使用状況アナライザーが、何千もの分散した一時ファイルを含むディレクトリにフラグを立てた場合は、そのディレクトリを選択し、**デュアル パネルで表示** を押します。 次に、**`Cmd+B`** (`cm_DirBranch`) を押して、ネストされたツリー全体を 1 つのリストボックスに平坦化し、キーボードの精度で項目を並べ替え、選択し、一括削除できるようにします。 

> [!重要]
 > **確定する前にクリーナーの選択を必ず確認してください**
 > システム クリーナーはキャッシュを **安全 (グリーン)** として指定しますが、一部の開発者ツール (Xcode DerivedData やローカル Docker ボリュームなど) は、次回プロジェクトの起動時に再コンパイルまたは再フェッチするのに時間がかかる場合があります。 チェックされたカテゴリを確認して、アクティブなスプリントのキャッシュをクリアしていないことを確認します。 

> [!注意]
 > **システムプロセスの強制終了 (`SIGKILL`)**
 > システム ステータス プロセス マネージャーで、`SIGKILL` (強制終了) を送信すると、開いているファイル バッファーをフラッシュしたり、ドキュメントの状態を保存したりすることなく、ターゲット プロセスが即座に停止されます。 常に最初に `SIGTERM` の正常な終了を試みてください。 

> [!警告]
 > **アプリサンドボックスコンテナの削除**
 > Mac App Store アプリケーションをアンインストールする場合、`~/Library/Containers/<BundleID>` に保存されている補助ファイルにはサンドボックス化されたドキュメント データベースが含まれることがよくあります。 コンテナーの削除を確認する前に、重要なローカル プロジェクト ファイルをエクスポートしていることを確認してください。
