# 第3章：日常のファイル操作と非同期バックグラウンドキュー

ファイル マネージャーは毎日、データをどれだけ速く、正確に、安全に操作できるかという 1 つの指標によって判断されます。 ATBCmder では、重なっている複数のウィンドウを操作したり、偶発的なドロップ エラーに耐えたり、大きなファイルの転送で画面がフリーズする間何もせずに待機したりする必要はありません。 

この章では、方向性のあるコピーと移動のワークフロー、インプレースのインライン名前変更、ワイルドカードを使用したパワーマーク、システムのドラッグ アンド ドロップの相互運用性、詳細な衝突処理、UNIX 権限とシンボリック リンク、マルチスレッドのバックグラウンド オペレーション キューなど、ファイル操作の全範囲について説明します。 

---

## 1. ビジュアルクイックスタート: 方向性操作モデル

オーソドックスなファイル マネージャーは、**ソース ➔ ターゲット** 方向モデルを使用します。 ファイル転送またはリンクの作成を開始すると、ATBCmder は **アクティブ パネル** (ソース) で選択された項目を取得し、**非アクティブ パネル** (ターゲット) で開かれているディレクトリに対して直接操作を実行します。 

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│  アクティブパネル (操作元 Source)                   非アクティブパネル (操作先 Target) │
│  /Users/brain/Downloads                             /Volumes/ExternalSSD/Projects      │
├──────────────────────────────────────────────┬───┬─────────────────────────────────────┤
│  名前                         サイズ 更新日時│ コ│  名前                         サイズ│
│  ▸ [..]                              --:--   │ ピ│  ▸ [..]                             │
│  ✔ database_dump.sql        1.8 GB   14:10   │ ｜│  ▸ client_portal                    │
│  ✔ schema_migration.sql      42 KB   14:12   │ ➔ │  ▸ microservices                    │
│  ● notes.txt                  4 KB   09:30   │ 対│  ● .env.production                  │
│                                              │ 側│                                     │
│  [2 項目を選択中: 1.8 GB]                    │   │  [転送先は準備完了・即座に書込可能] │
├──────────────────────────────────────────────┴───┴─────────────────────────────────────┤
│  [F5] コピー     [F6] 移動     [Shift+F5] 同一複製     [F8 / ⌘⌫] ゴミ箱へ移動          │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### デュアル マトリックス コアの操作に関するチートシート

| アクション | macOS ショートカット | クラシック コマンダー キー | コマンドID | 説明 |
 | :--- | :--- | :--- | :--- | :--- |
 | **ターゲットにコピー** | `F5` / `Fn+F5` | `F5` | `cm_Copy` | 選択した項目を反対側のパネルにコピーします。 |
 | **同じパネルにコピー** | `Shift+F5` / `⇧F5` | `Shift+F5` | `cm_CopySamePanel` | 名前変更プロンプトを表示して、アクティブなパネル内の項目を複製します。 |
 | **ターゲットに移動** | `F6` / `Fn+F6` | `F6` | `cm_Move` | 選択した項目を反対側のパネルに移動します。 |
 | **新しいフォルダー (MkDir)** | `F7` / `Fn+F7` | `F7` | `cm_MkDir` | アクティブなパネルに新しいディレクトリを作成します。 |
 | **ゴミ箱に削除** | `F8` / `⌘⌫` | `F8` / `Delete` | `cm_Delete` | 選択したアイテムを macOS のゴミ箱に移動します。 |
 | **永久削除** | `Shift+Delete` / `⇧⌦` | `Shift+F8` | `cm_Delete` | ゴミ箱をバイパスし、ファイルのリンクを完全に解除します。 |
 | **インラインのクイック名前変更**| `F2` / `Shift+F6` | `Shift+F6` | `cm_RenameOnly` | テーブル行内のアクティブな項目の名前を直接変更します。 |
 | **ファイルのプロパティ** | `Alt+Enter` / `⌥⏎` | `Alt+Enter` | `cm_SetFileProperties` | UNIX 権限、タイムスタンプ、およびメタデータのダイアログを開きます。 |
 | **フォルダー容量の計算**| `Alt+Shift+Enter` / `⌥⇧⏎` | `Alt+Shift+Enter` | `cm_CountDirContent` | ディレクトリの再帰バイトを計算します (選択した合計の `Ctrl+L` / `cm_CalculateSpace`)。 |
 | **バックグラウンドキュー** | `Toolbar ⚡` | — | `cm_OperationsPanel` | 3キューバックグラウンド転送モニターを開きます。 |

### 視覚的なランドマーク: 中央のツールバー

ATBCmder は、2 つのパネルを分離する中央の仕切りに直接埋め込まれた専用の垂直クイックアクション ツールバーを備えています。 

![Middle Toolbar](images/middle_toolbar.png)
 *中央の中央ツールバーでは、表示 (F3)、編集 (F4)、コピー (F5)、移動 (F6)、新規フォルダー (F7)、削除 (F8)、およびパネル交換にマウスで瞬時にアクセスできます。

## 2. コア操作: コピー、移動、MkDir、および削除

毎日のファイル管理は、コピー、移動、ディレクトリの作成、不要なファイルの削除という 4 つの主要なアクションを中心に展開されます。

### 2.1 ファイルのコピー (`F5` / `cm_Copy`)

ファイルまたはディレクトリをコピーするには:

 1. キーボードまたはマウスを使用して、アクティブなパネルで 1 つ以上の項目を **選択**します。 
2. **`F5`** を押します (Apple キーボードの場合は `Fn+F5`、または中央のツールバーの **コピー** をクリックします)。 
3. **コピー ダイアログ**が表示されます。 
- **宛先行**: 反対側のパネルの現在のディレクトリ パスが自動的に入力されます。 このパスを手動で編集したり、新しいサブフォルダー名を追加してコピーと作成を同時に行うことも、`...` をクリックして参照することもできます。 
- **開始 (`Enter`)**: リアルタイムの進行状況ダイアログを表示して、即時フォアグラウンド コピーを開始します。 
- **キューに追加 (`F2`)**: バックグラウンドで実行する転送をキューに入れます ([セクション 7.4](#74-cm_operationspanel) を参照)。 
- **オプション**: 高度な競合ルール、属性の保存、チェックサム検証を拡張します。 

```
┌────────────────────────────────────────────────────────┐
│ Copy file(s)                                           │
│ Copy selected 3 files?                                 │
│ To: [/Volumes/Backup/Assets                          ] │
│ [Options ▼]   [Add To Queue #1 ▾]   [Cancel]   [Start] │
└────────────────────────────────────────────────────────┘
```

#### パネル内重複 (`Shift+F5` / `cm_CopySamePanel`)

現在のディレクトリ内のファイルのクローンをすばやく作成するには (たとえば、`nginx.conf` を編集する前にバックアップを作成する):

 - 項目を強調表示して、`Shift+F5` (または `⇧F5`) を押します。 
- ATBCmder は、*同じ* ディレクトリ内の宛先パスを示すプロンプトを表示し、新しい名前 (`nginx.conf.bak` など) を入力できるようにします。

#### 標準 macOS クリップボード (`Cmd+C` ➔ `Cmd+V`)

ATBCmder は、macOS システムのクリップボード ショートカットと完全に統合されています。 

- **`Cmd+C` (`⌘C`)**: 選択したファイル パスをクリップボードにコピーします (`cm_CopyToClipboard`)。 
- **`Cmd+V` (`⌘V`)**: ファイルをクリップボードからアクティブなパネルに貼り付けます (`cm_PasteFromClipboard`)。 
- **`Cmd+Option+V` (`⌥⌘V`)**: クリップボード ファイルをアクティブ パネルに移動します (`cm_PasteAsMove`)。 

---

### 2.2 ファイルの移動 (`F6` / `cm_Move`)

移動すると、ファイルがソース ディレクトリからターゲット ディレクトリに転送されます。 

1. 項目を選択し、**`F6`** を押します (または `Fn+F6` / 中央のツールバーの **移動** をクリックします)。 
2. **移動ダイアログ**が開き、ターゲット パネルのパスが表示されます。 
3. **`Enter`** を押して次を実行します。 
- **同一ファイルシステムの移動**: RAW ディスク ブロックを移動せずにファイルシステム カタログ参照を更新することで、APFS/HFS+ ボリューム上で瞬時かつアトミックに実行できます。 
- **ファイルシステム間移動**: ボリューム全体でデータを宛先にストリーミングし、バイト完了を確認し、到着が確認されたらソースを安全に削除します。 
4. 同じ名前の既存のファイルが宛先に存在する場合、ATBCmder は一時停止し、**上書きダイアログ** を呼び出します ([セクション 6](#6) を参照)。 

---

### 2.3 新しいディレクトリの作成 (`F7` / `cm_MkDir`)

フォルダー構造をその場で作成する必要がありますか?

 1. **`F7`** (または `Fn+F7` / `Shift+Cmd+N` / `cm_MkDir`) を押します。 
2. 軽量のプロンプト: `Enter folder name:` が表示されます。 
3. フォルダー名を入力し、`Enter` を押します。 

```
┌──────────────────────────────────────────────┐
│ Create Directory                             │
│ Enter folder name:                           │
│ [2026-09-Q3_Reports                        ] │
│                      [Cancel]      [OK (⏎)]  │
└──────────────────────────────────────────────┘
```

#### サブディレクトリの連鎖

ネストされたフォルダー階層を 1 つの手順で作成できます。 `deep/nested/project/assets` と入力すると、4 つの階層レベルすべてが即座に作成されます (`mkdir -p` と同等)。

#### オートフォーカスの配置

作成時に、ATBCmder は自動的にパネル カーソルを新しいフォルダーに直接配置し、すぐに入力 (`Enter`) またはファイル転送できるようにします。 

---

### 2.4 ファイルの削除: macOS のゴミ箱と永久パージ

安全性と回復可能性が最も重要です。 ATBCmder は二重削除ワークフローをサポートしています。 

```
                  ┌────────────────────────────────────────┐
                  │          File Deletion Trigger         │
                  └───────────────────┬────────────────────┘
                                      │
                 ┌────────────────────┴───────────────────┐
                 ▼                                        ▼
    [ F8 / Delete / Cmd+Backspace ]             [ Shift+Delete / Shift+F8 ]
                 │                                        │
                 ▼                                        ▼
    macOS System Trash (.Trash)                  Permanent Unlink
      • Fully recoverable                         • Bypasses Trash
      • Put Back support in Finder                • Zero disk footprint
      • Volume .Trashes directory                 • Unrecoverable without deep carve
```

#### macOS のゴミ箱への削除 (`F8` / `Delete` / `Cmd+Backspace`)

- 選択したファイルは、macOS `send2trash` API を介してシステムのゴミ箱に送られます。 
- ファイルは、macOS Finder 経由でいつでも検査または復元できます (「元に戻す」)。 
- 確認ダイアログは **環境設定** (`operations.confirm_delete`) で有効または非表示にすることができます。

#### 永久即時削除 (`Shift+Delete` / `Shift+F8`)

- ゴミ箱を完全にバイパスし、ただちにファイルのリンクを解除し、ストレージ領域を解放します。 
- ゴミ箱バッファの制限やディスクの枯渇によりステージングが妨げられる、マルチギガバイトの仮想マシンやディスク イメージをクリアするのに最適です。

#### ゴミ箱のサポートのないボリューム (`trash_unavailable` 検出)

特定のネットワーク共有 (SMB、NFS)、仮想ファイルシステム (`vfs://`)、または `.ゴミ箱es` ディレクトリのないレガシー FAT/exFAT ファイルシステムでフォーマットされた外部ドライブから削除する場合、macOS はアイテムをゴミ箱に送信できません。 

このような場合、ATBCmder はインテリジェントな安全警告をトリガーします。 
```
┌────────────────────────────────────────────────────────┐
│ Trash Unavailable                                      │
│ The volume containing '/Volumes/NAS/backup.iso' does   │
│ not support Trash.                                     │
│ Would you like to permanently delete this file?        │
│                                                        │
│ [✔] Apply to all remaining items                       │
│              [Skip]               [Delete Permanently] │
└────────────────────────────────────────────────────────┘
```

 **完全に削除**、**スキップ**、または**残りのすべてのアイテムに適用**を選択して、大規模な一括削除を無人で処理できます。

#### 安全なマルチパス シュレッディング (`Alt+Delete` / `cm_Wipe`)

RAW フラッシュ回復ツールを使用して回復できない状態にしておく必要がある機密文書、資格情報、または秘密キーの場合:

 - 項目をハイライト表示し、**メニュー ファイル** → **ワイプ** (`Alt+Delete` / `cm_Wipe`) を選択します。 
- ATBCmder は、inode のリンクを解除する前に、ランダムなビット パターンとゼロを使用してマルチパス上書きを実行します。

## 3. インラインのクイック名前変更と名前編集

単一ファイルの名前を変更する場合、複雑なメニューやダイアログ ポップアップは必要ありません。 ATBCmder は、テーブル行を迅速にその場で編集できます。 

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│  Name                                  Ext      Size      Date Modified         │
│  ▸ [..]                                         --:--     drwxr-xr-x            │
│  ● Annual_Financial_Report_2025        .pdf     4.2 MB    Today, 11:20          │
│    ▲                                                                            │
│    └── [Editable Text Box: Stem highlighted, .pdf extension preserved]          │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### インライン名前変更のトリガー

1. パネル内の任意のファイルまたはディレクトリを強調表示します。 
2. **`F2`** または **`Shift+F6`** (`cm_RenameOnly`) を押すか、すでに強調表示されているファイル名を 1 回クリックします。 
3. テーブルのセルがインライン エディター (`QLineEdit`) に変換されます。

### インテリジェントな拡張機能の保存

`invoice_september.pdf` などのファイル名を変更する場合:

 - ATBCmder は、ベース ファイル名 (`invoice_september`) のみを自動的に事前選択します。 
- ファイル拡張子 (`.pdf`) は選択されずそのまま残り、macOS ファイルの関連付けを壊すような誤った拡張子の削除を防ぎます。 
- 拡張子を変更する場合は、矢印キーを使用するか、編集ボックス内で `Cmd+A` を押します。

### インライン名前変更内のキーボード ショートカット

- **`Enter` (`Return`)**: 新しい名前をコミットし、パネルのインデックスを再作成します。 
- **`Esc`**: 編集をキャンセルし、変更せずに元の名前に戻します。 
- **`Tab`**: 現在の名前をコミットし、リスト内の *次* のファイルの名前変更を即座に開始します。これにより、キーボードから離れることなく高速で順次ファイルの名前変更が可能になります。

## 4. 選択テクニック: パワーマーキング ファイル

従来のファイル マネージャーでは、カーソルの位置と選択内容は密接に関連しています。`Cmd` を押し続けない限り、カーソルを移動すると前のファイルの選択が解除されます。 ATBCmder では、**カーソル フォーカス** と **マークされた選択範囲** が分離され、正確なバッチ ステージングが可能になります。 

```
  Status Column:
  [ ]  Unselected (cursor may or may not be on row)
  [✔]  Marked / Selected (accumulated into operation payload)
```

### 4.1 グローバル選択アクション

| アクション | macOS ショートカット | クラシックキー | コマンドID | 説明 |
 | :--- | :--- | :--- | :--- | :--- |
 | **すべて選択** | `Cmd+A` / `⌘A` | `Ctrl+A` / `Ctrl+Num+` | `cm_MarkMarkAll` | アクティブなパネル内のすべてのファイルとフォルダーをマークします。 |
 | **すべて選択を解除** | `Cmd+Shift+A` / `⇧⌘A`| `Ctrl+Shift+A` / `Ctrl+L` | `cm_MarkUnmarkAll` | アクティブなパネル内のすべてのマークをクリアします。 |
 | **選択範囲を反転**| `Num*` / `⌥⌘I` | `Num*` | `cm_MarkInvert` | 選択状態を反転します。マークされた状態がマークされていない状態になり、その逆も同様です。 |

 ---

### 4.2 パターンとワイルドカードの選択

ワイルドカードを選択すると、数回のキーストロークで、数千のディレクトリ内の数百の特定のファイルをターゲットにすることができます。 

```
┌────────────────────────────────────────────────────────┐
│ Mark Files by Pattern                                  │
│ Pattern: [*.jpg;*.png;*.webp                        ]  │
│                                                        │
│ [✔] Case sensitive       [ ] Regular expression        │
│                      [Cancel]                 [OK (⏎)] │
└────────────────────────────────────────────────────────┘
```

#### マークグループ (`Num+` / `cm_MarkPlus`)

- **`Num+`** (キーパッド プラス、またはメニュー **マーク** → **グループの選択**からトリガー) を押します。 
- 標準シェルのワイルドカードを入力します。 
- `*.log`: `.log` で終わるすべてのファイルをマークします。 
- `*.jpg;*.png;*.webp`: 複数の拡張子を一度に照合するためのセミコロン区切りのリスト。 
- `data_2026_??.csv`: 2 桁の月次ファイル (`01` ～ `12`) と一致します。 
- `*draft*`: 「draft」という単語を含むファイルと一致します。 
- `Enter` を押すと、一致するすべてのエントリが即座に選択されます。

#### グループのマークを解除 (`Num-` / `cm_MarkMinus`)

- **`Num-`** (キーパッドのマイナス) を押します。 
- 既存の選択項目から一致する項目を削除するパターンを入力します (例: `*test*`)。

#### すべてを同じ拡張子でマーク (`Shift+Num+` / `cm_MarkCurrentExtension`)

- 任意のファイル (`app.tsx` など) にカーソルを置きます。 
- **`Shift+Num+`** を押します。 
- 現在のディレクトリ内のすべての `.tsx` ファイルが即座に選択されます。 

---

### 4.3 範囲とポイントの選択

- **連続ブロック選択 (`Shift+Up` / `Shift+Down`)**: `Shift` を押しながら矢印キーで移動すると、連続した選択ブロックが上または下に拡張されます。 
- **単一項目切り替え (`Space` / `Insert` / `cm_SelectOrDeselectFile`)**:
 - `Space` を押すと、カーソル下の項目がマークまたはマーク解除され、フォルダ上の場合はディレクトリ サイズがすぐに計算されます。 
- `Insert` (または特定の Mac キーボードでは `Fn+Return`) を押すと項目がマークされ、カーソルが自動的に次の行に移動し、1 本の指で迅速な選択パスが可能になります。 
- **マウスとトラックパッド**:
 - `Cmd+Click`: 他の選択を変更せずに、個々の行の選択を切り替えます。 
- `Shift+Click`: 現在のアンカー行からクリックされた行まで選択範囲を拡張します。

### ステータスバーのライブ選択テレメトリ

ファイルがマークされると、下部のステータス バーがすぐに更新されます。 
```
[ 48 items | 12 selected (284.6 MB) ]   [ Volume Free: 184.2 GB / 494.3 GB ]
```

 大規模なコピーや削除を行う前に、正確なバイト ペイロードをリアルタイムで状況認識できます。

## 5. ドラッグアンドドロップの相互運用性

ATBCmder は、オーソドックスなワークフローおよび macOS デスクトップ エコシステムとの完全な互換性を維持しながら、ドラッグ アンド ドロップを第一級の機能として扱います。 

```
       Dual-Panel Transfer                       External macOS Desktop
 ┌──────────────┐   ┌──────────────┐       ┌──────────────┐   ┌──────────────┐
 │ Left Panel   │══►│ Right Panel  │       │ ATBCmder     │══►│ Finder / App │
 │ (Source)     │   │ (Target)     │       │ Panel        │   │ (Desktop)    │
 └──────────────┘   └──────────────┘       └──────────────┘   └──────────────┘
```

### パネル間のドラッグ

- マークされた項目をクリックして、アクティブなパネルから中央のスプリッターを横切って非アクティブなパネルにドラッグします。 
- ファイル テーブル内の任意の場所にドロップすると、宛先フォルダーへの転送が開始されます。 
- **サブフォルダーへのドロップ**: 特定のサブディレクトリ行に直接ドロップすると、ATBCmder はペイロードをパネル ルートではなくそのサブフォルダーにルーティングします。

### macOS Finder、デスクトップ、外部アプリとの対話

- **ATBCmder へのドラッグ**: ファイルを Finder、デスクトップ、または AirDrop ダウンロードからいずれかの ATBCmder パネルに直接ドラッグして、コピーまたは移動します。 
- **ATBCmder からのドラッグアウト**: ファイルを ATBCmder から VS Code、ターミナル (ファイル パスを貼り付ける)、Slack、Apple Mail、または Web ブラウザのアップロード ボックスに直接ドラッグします。

### ドラッグ中の修飾キー

| 修飾キー | ドラッグアクション | マウスカーソルアイコン | 説明 |
 | :--- | :--- | :--- | :--- |
 | **修飾子なし** | デフォルトのアクション | 標準の矢印 | ボリューム間のコピー。 同じボリューム内で移動します。 |
 | **オプション (`⌥`)** | **強制コピー** | 緑色の `+` バッジ | 常にアイテムをコピーし、ソース ファイルはそのまま残します。 |
 | **コマンド (`⌘`)** | **強制移動** | 曲線矢印バッジ | 写真 曲線矢印バッジ 常にアイテムを移動し、到着時にソース ファイルのリンクを解除します。 |

### スプリング式フォルダー

ATBCmder でネストされたディレクトリ上にファイルをドラッグする場合:

 - **750 ミリ秒**、ターゲット フォルダーの上にマウス カーソルを置きます。 
- フォルダーが自動的に点滅して開き、内部に移動します。 
- マウス ボタンを放さずに、複数のレベルをネストされたサブディレクトリの奥深くに移動し、ペイロードを目的の場所に正確にドロップできます。

## 6. 衝突の処理と衝突の解決

名前の衝突は、ファイル管理において最も危険な瞬間です。 間違ったファイルを上書きすると、何時間もの作業が無駄になる可能性があります。 ATBCmder は、ファイルを上書きする前に検査し、きめ細かい安全制御を提供するエンタープライズ グレードの競合解決エンジンを実装しています。 

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ Confirm File Overwrite                                                                 │
│                                                                                        │
│ File already exists at the destination.                                                │
│                                                                                        │
│ Source:      /Users/brain/Downloads/build_artifacts.zip                                │
│ Source info: 124,518,400 bytes, 2026-09-06 14:15                                       │
│                                                                                        │
│ Destination: /Volumes/Backup/build_artifacts.zip                                       │
│ Dest info:   118,204,112 bytes, 2026-09-01 09:30                                       │
│                                                                                        │
│ Would you like to overwrite it?                                                        │
│                                                                                        │
│ [Skip All]   [Overwrite All]   [Rename]   [Auto-rename]                                │
│                                                                                        │
│ [Cancel]                                        [Skip]               [Overwrite (⏎)]   │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 上書きダイアログの内訳

ターゲットの衝突が発生すると、ATBCmder は **ファイルの上書きの確認** ダイアログを表示します。 

1. **並列メタデータ検査**:
 - 正確なファイル サイズを 1 バイトまで比較します。 
- 変更日とタイムスタンプを比較します。 ソース ファイルのサイズが新しいか古いか、または同じかが顕著に強調表示されます。 
2. **現在のアイテム決定ボタン**:
 - **上書き (`Enter`)**: 競合する宛先ファイルをソース ファイルで置き換えます。 
- **スキップ**: 既存の宛先ファイルをそのまま残して、転送バッチ内の次の項目に進みます。 
- **キャンセル (`Esc`)**: 残りの操作を直ちに中止し、既に転送されているファイルはすべて保持します。 
3. **バッチと安全措置**:
 - **すべて上書き**: この転送ジョブの後続の競合ファイルをすべてサイレントに上書きします。 
- **すべてスキップ**: 再度プロンプトを表示せずに、競合する残りのファイルをすべてスキップします。 
- **名前の変更**: 書き込む前に、コピーされたファイルのカスタムの新しい名前を入力するように求められます。 
- **自動名前変更**: 増分カウンター (`build_artifacts_1.zip`、`build_artifacts_2.zip` など) を自動的に追加し、手動介入なしで両方のバージョンが並べて保存されるようにします。 

---

### 「コピー」ダイアログでの事前構成された衝突ポリシー

大規模な自動バッチ ジョブや無人バックアップの場合は、[コピー/移動] ダイアログの展開可能な [**オプション**] パネル内で、競合動作を事前に構成できます。 

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Copy Options Panel                                                           │
│ ┌─ Conflict Resolution ─────────────────┐ ┌─ Attributes & Behaviors ──────┐  │
│ │ When file exists:      [Ask          ▾]│ │ [✔] Check free space          │ │
│ │ When directory exists: [Merge        ▾]│ │ [✔] Copy date/time            │ │
│ │ When cannot set attr:  [Skip         ▾]│ │ [✔] Copy attributes           │ │
│ └───────────────────────────────────────┘ │ [ ] Drop readonly flag        │  │
│ ┌─ Filters ─────────────────────────────┐ │ [✔] Copy ownership (POSIX)     │ │
│ │ [ ] Exclude empty directories         │ │ [✔] Verify after copy: [SHA256]│ │
│ └───────────────────────────────────────┘ └───────────────────────────────┘  │
│ [Save these options as default]                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```


 - **ファイルが存在する場合**:
 - `Ask`: 衝突のたびに上書きダイアログを表示します (デフォルト)。 
- `Overwrite`: 既存のファイルを自動的に上書きします。 
- `Skip`: 競合するファイルを自動的にスキップします。 
- `Overwrite older`: ソース変更時刻の方が新しい場合にのみ宛先を上書きします。 
- `Rename copied`: コピーされたファイルにカウンター サフィックス (`_1`、`_2`) を追加します。 
- `Auto-rename target`: 既存のターゲット ファイルの名前を変更し、新しいファイルを元の名前で書き込みます。 
- **ディレクトリが存在する場合**:
 - `Merge`: フォルダーの内容を再帰的に結合します。 競合しないサブファイルは既存のフォルダーにコピーされます。 
- `Ask` / `Overwrite` / `Skip`。 
- **高度な検証と属性**:
 - **空きスペースの確認/スペースの予約**: 開始前にソースバイトを事前に計算し、宛先ボリュームに適切な容量があることを確認します。 
- **コピー後の検証**: ソース ファイルと書き込まれた宛先ファイルの両方で暗号化チェックサム (`SHA-256`、`MD5`、`SHA-1`、`CRC32`) を計算し、サイレント ストレージ破損に対して 100% のデータ整合性を保証します。 
- **リンクをたどる**: シンボリックリンクをポインタ参照としてコピーするか、完全な物理コピーに逆参照するかを制御します。 
- **日付/時刻と所有権をコピー**: POSIX の作成日、変更タイムスタンプ、およびユーザー/グループの所有権 ID を保持します。

## 7. ⚡ プロのヒントと詳細: 高度なファイル システムのパワー

デュアルパネル管理をマスターするには、macOS の基礎となる UNIX 基盤を理解する必要があります。 ここでは、開発者、システム管理者、ストレージ専門家向けに設計された強力な機能を紹介します。

### 7.1 シンボリック リンクとハード リンク (`cm_SymLink`、`cm_HardLink`)

macOS は Darwin UNIX 上に構築されており、次の 2 つの異なるリンク タイプを提供します。 

```
  Symbolic Link (Symlink):
  [ Symlink File ] ──(Path Pointer)──► [ Target File / Directory ]
  • Can cross volume boundaries
  • Can point to directories
  • Breaks if target is moved

  Hard Link:
  [ Hard Link Entry ] ──┐
                        ├──(Direct Inode Reference)──► [ Raw Disk Blocks ]
  [ Original Entry  ] ──┘
  • Cannot cross filesystem boundaries (same APFS container)
  • Files only (no directory hard links on macOS)
  • Data persists until all hard links are deleted
```

#### シンボリック リンクの作成 (`cm_SymLink`)

1. アクティブなパネルで 1 つ以上のファイル/フォルダーを強調表示します。 
2. **メニュー ファイル** → **シンボリック リンクの作成...** (`cm_SymLink`) を選択します。 
3. ATBCmder は、ソース項目の絶対パスを指すシンボリックリンクを反対側のパネルに自動的に生成します。 
4. シンボリックリンクは、パネル内に個別の `l` 属性フラグ (例: `lrwxr-xr-x`) を表示します。

#### ハードリンクの作成 (`cm_HardLink`)

1. ローカル APFS/HFS+ ボリューム上のファイルを強調表示します。 
2. **メニュー ファイル** → **ハード リンクの作成...** (`cm_HardLink`) を選択します。 
3. ATBCmder は、まったく同じ i ノードを共有するターゲット パネルに追加のディレクトリ エントリを作成します。 
4. いずれかのファイルに書き込まれた変更は、両方のファイルに即座に反映されます。 1 つのファイルを削除しても、リンク数が 0 になるまでデータは削除されません。 

> [!NOTE]
 > **リンク境界の制限**: ハード リンクはボリューム境界を越えたり、ネットワーク共有上に作成したりすることはできません (`vfs://`)。 異なるドライブまたはリモート マウント ポイント間でリンクする場合は常に、シンボリックリンクを使用する必要があります。 

---

### 7.2 ファイルのアクセス許可と属性 (`Alt+Enter` / `cm_SetFileProperties`)

包括的な **プロパティ ダイアログ**を使用して、POSIX ファイル属性を検査および変更します。 

```
┌────────────────────────────────────────────────────────┐
│ Properties - production_api.py                         │
│ ┌─ Metadata ─────────────────────────────────────────┐ │
│ │ Full Path:     /Users/brain/work/production_api.py │ │
│ │ Size:          84,210 bytes                        │ │
│ │ Created:       2026-03-12 10:14:22                 │ │
│ │ Last Modified: 2026-09-06 13:45:01                 │ │
│ │ Last Accessed: 2026-09-06 15:30:10                 │ │
│ └────────────────────────────────────────────────────┘ │
│ ┌─ Permissions (UNIX) ───────────────────────────────┐ │
│ │ Octal Mode: [ 755 ]                                │ │
│ │ ┌─ Owner ──┐   ┌─ Group ──┐   ┌─ Others ─┐         │ │
│ │ │ [✔] Read │   │ [✔] Read │   │ [✔] Read │         │ │
│ │ │ [✔] Write│   │ [ ] Write│   │ [ ] Write│         │ │
│ │ │ [✔] Exec │   │ [✔] Exec │   │ [✔] Exec │         │ │
│ │ └──────────┘   └──────────┘   └──────────┘         │ │

 1. **トリガー**: 任意のファイルまたはディレクトリを強調表示し、**`Alt+Enter`** (`⌥⏎` / `cm_SetFileProperties`) を押します。 
2. **メタデータ レビュー**: 完全なファイル パス、正確なバイト数、作成時間 (`btime`)、変更時間 (`mtime`)、および最終アクセス時間 (`atime`) を表示します。 
3. **UNIX 権限マトリックス**:
 - **対話型チェックボックス**: **所有者**、**グループ**、**その他**の読み取り (`r`)、書き込み (`w`)、および実行 (`x`) 権限を個別に切り替えます。 
- **双方向 8 進数入力**: **8 進数モード** フィールドに 8 進数を直接入力します (例: 実行可能ファイルの場合は `755`、標準ドキュメントの場合は `644`、秘密 SSH キーの場合は `600`)。 チェックボックスはリアルタイムで更新され、その逆も同様です。 
4. `OK` (`Enter`) を押して、POSIX `chmod` 経由で変更を適用します。

### 7.3 占有スペースの計算 (`cm_CountDirContent` / `cm_CalculateSpace` / `Space`)

デフォルトでは、ファイル マネージャーはディレクトリ サイズを `<DIR>` または `--` として表示します。これは、何百万ものファイルにわたるフォルダー サイズを再帰的に計算すると、ファイル システムのパフォーマンスが低下するためです。 ATBCmder を使用すると、オンデマンドで即座に計算できます。 

- **単一フォルダー サイズ (`Space` / `Insert` / `cm_SelectOrDeselectFile`)**: 任意のフォルダー上で `Space` を押します。 ATBCmder は、フォルダーの合計再帰バイトをバックグラウンドで計算し、`<DIR>` を正確なサイズ (例: `14.2 GB`) に置き換えます。 
- **アクティブ パネル内のすべてのフォルダー (`Alt+Shift+Enter` / `⌥⇧⏎` / `cm_CountDirContent`)**:
 - 現在のパネルに表示されているすべてのディレクトリをスキャンします。 
- 正確なバイト合計でテーブルの行を更新します。 
- **選択されたディレクトリの累積サイズ (`Ctrl+L` / `⌃L` / `cm_CalculateSpace`)**:
 - 選択したフォルダーの合計再帰バイトを蓄積し、ファイル数、フォルダー数、ストレージ サイズをステータス バーに要約します。 

---

### 7.4 バックグラウンド操作キュー (`cm_OperationsPanel`)

50 GB の大きなビデオ撮影をコピーしたり、数十万の小さなソース コード ファイルを転送したりしても、ファイル マネージャーがフリーズすることはありません。 ATBCmder には **3 キュー非同期転送エンジン** が組み込まれています。 

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ Background Operations                                                                  │
│ ┌─ [Queue #1 (Active)] ───────────┬─ [Queue #2 (Idle)] ───┬─ [Queue #3 (Idle)] ──────┐ │
│ │                                                                                    │ │
│ │ [RUNNING] Copy: 14 items -> /Volumes/BackupDrive/Media                             │ │
│ │   Current: RED_4K_Clip_0042.r3d (2.4 GB / 8.6 GB)                                  │ │
│ │   Speed: 428.5 MB/s | ETA: 00:01:14                                                │ │
│ │   [████████████████████████████████░░░░░░░░░░░░░░░░░░] 64%                         │ │
│ │                                                                                    │ │
│ │ [QUEUED] Move: 4 items -> /Volumes/BackupDrive/RAW_Audio                           │ │
│ │ [COMPLETED] Copy: 28 items -> /Users/brain/Projects/Website                        │ │
│ │                                                                                    │ │
│ └────────────────────────────────────────────────────────────────────────────────────┘ │
│                                         [Cancel Task]   [Clear Completed]   [Close]    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

#### なぜ 3 つの独立したキューがあるのでしょうか?

- **各キュー内でシリアル化**: **キュー #1​​* 内のタスクは、厳密な FIFO 順序で次々に実行されます。 これにより、機械式ハードドライブ上のディスクヘッドのスラッシングが防止され、競合のボトルネックが回避されます。 
- **キュー間での並列**: **キュー #1​​*、**キュー #2**、**キュー #3** は、別々のバックグラウンド スレッド (`QThread`) で同時に動作します。 **NVMe SSD A** をターゲットとする転送をキュー #1​​ に、**外部 USB ドライブ B** をターゲットとする転送をキュー #2 に、ネットワーク NAS アップロードをキュー #3 に割り当てることができ、最大の総バス スループットを実現します。

#### ジョブをキューに送信する

1. アクティブなパネルでファイルを選択し、`F5` (コピー) または `F6` (移動) を押します。 
2. [開始] をクリックする代わりに、[**キュー #1​​* に追加] をクリックします (または、ドロップダウンの山形をクリックして **キュー #2** または **キュー #3** を選択します)。 
3. ダイアログはすぐに閉じられ、メイン ウィンドウが解放されて参照やナビゲーションを継続できるようになります。

#### キュー ウィンドウの管理 (`cm_OperationsPanel`)

- メイン ツールバーの **⚡ キュー** ボタンをクリックするか、**メニュー コマンド** → **バックグラウンド オペレーション** (`cm_OperationsPanel`) を選択します。 
- **リアルタイム テレメトリ**: アクティブなタスク、現在の転送ファイル、ストリーミング転送速度 (`428.5 MB/s` など)、および計算された ETA カウントダウンを検査します。 
- **色分けされたステータス**:
 - `[QUEUED]`: 列に並んで待っています。 
- `[RUNNING]`: データをアクティブに転送しています。 
- `[COMPLETED]`: バイト数が確認され、正常に終了しました。 
- `[FAILED]`: I/O エラーが発生しました (エラー メッセージがインラインで表示されます)。 
- `[CANCELLED]`: ユーザーによって中止されました。 
- **コントロールアクション**:
 - **タスクのキャンセル**: 選択したキューに入れられた転送または実行中の転送を安全に終了します。 
- **完了のクリア**: 完了したジョブ、失敗したジョブ、およびキャンセルされたジョブをリストから削除します。 
- **バックグラウンド競合の解決**: バックグラウンド タスクで上書き競合が発生した場合、ATBCmder によって通知が生成されるため、他の並行タスクを中止することなく競合を解決できます。

Step 6: Click the queue dropdown chevron and choose [Queue #2].
Step 7: Press Toolbar ⚡ (cm_OperationsPanel) to watch both queues stream concurrently.
```

 *結果: ファイルの参照、メモの編集、またはアセットの名前変更を続行しながら、ハードウェア バスが完全に飽和した状態で両方のカードが同時に取り込まれます。*

## 9. 安全性とシステムの警告

> [!WARNING]
 > **外部ドライブおよびネットワーク ドライブの完全な削除**:
 > FAT32、exFAT、または NTFS (サードパーティ製ドライバー経由) およびリモート ネットワーク共有 (SMB/SFTP) でフォーマットされた外部ドライブには、多くの場合、macOS システム `.ゴミ箱es` ディレクトリがありません。 これらのボリュームから項目を削除すると、ATBCmder はゴミ箱が使用できないことを警告します。 このアクションを確認すると、ファイルが**永久に削除**されます。 確認する前に必ずパスヘッダーを再確認してください。 

> [!CAUTION]
 > **バッチ操作でのファイルの上書き**:
 > 衝突ダイアログで **すべて上書き** を使用すると、ATBCmder はそのジョブ全体に対するそれ以上の衝突アラートを抑制します。 ソース ディレクトリに誤って重複したファイル名が含まれている場合、既存のターゲット ファイルは元に戻せないように置き換えられます。 無人バッチ コピーには、**自動名前変更** または **古いものを上書き** を使用することを検討してください。 

> [!IMPORTANT]
 > **APFS ハードリンクの制限事項**:
 > ハード リンクは、異なる APFS ボリューム、ディスク パーティション、またはディスク イメージにまたがることはできません。 2 つの異なるマウント ポイント間 (`/Users/...` から `/Volumes/ExternalDrive/...` など) にハード リンクを作成しようとすると、操作は失敗します。 異なるストレージ ボリューム間でリンクする場合は常に、**シンボリック リンク** (`cm_SymLink`) を使用してください。 

> [!TIP]
 > **NVMe 転送速度の最適化**:
 > ATBCmder は、最新の Apple Silicon ユニファイド メモリおよび PCIe 4.0/5.0 NVMe SSD 向けに最適化されています。 デフォルトでは、ファイル操作は高性能 **1 MB コピー バッファ** (`operations.copy_buffer_size`) を利用します。 このバッファは、ハイエンド 10GbE ネットワーク インターフェイスや特殊なストレージ アレイに合わせて、**環境設定** → **ファイル操作** で微調整できます。
