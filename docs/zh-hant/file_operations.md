# 第 3 章：日常檔案操作與後台異步隊列

評價一款檔案管理器是否優秀，最核心的指標始終是：**運算元據時究竟有多快、多準、多安全**。在 ATBCmder 中，你再也不需要在桌面上一層層翻找重疊混亂的視窗，不必擔心滑鼠誤拖誤放，更無需在傳輸數十 GB 大檔案時面對卡死的主介面苦苦等待。

本章將全景式解析日常檔案操作的所有環節：方向性複製與移動工作流、行內即時快速改名、萬用字元高能批次標記、系統級拖曳互操作、衝突覆蓋智慧仲裁引擎、UNIX 許可權與軟硬連結管理，以及基於多執行緒的 3 通道後臺操作佇列。

---

## 1. 快速上手：方向性操作模型

正統 Commander 類軟體普遍遵循經典的**“源路徑 ➔ 目標路徑 (Source ➔ Target)”**方向性模型。當你發起檔案傳輸或建立連結時，ATBCmder 會自動以**當前啟用面板（源）**中選中的專案為基準，將其直接處理到**對側閒置面板（目標）**當前開啟的目錄中。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│  啟用面板 (源目錄 Source)                            對側面板 (目標目錄 Target)        │
│  /Users/brain/Downloads                             /Volumes/ExternalSSD/Projects      │
├──────────────────────────────────────────────┬───┬─────────────────────────────────────┤
│  名稱                         大小   修改時間│   │  名稱                         大小  │
│  ▸ [..]                              --:--   │   │  ▸ [..]                             │
│  ✔ database_dump.sql        1.8 GB   14:10   │ 復│  ▸ client_portal                    │
│  ✔ schema_migration.sql      42 KB   14:12   │ 製│  ▸ microservices                    │
│  ● notes.txt                  4 KB   09:30   │ ➔ │  ● .env.production                  │
│                                              │ 對│                                     │
│  [已選中 2 個檔案: 1.8 GB]                   │ 側│  [目標目錄就緒，隨時可接收寫入]     │
├──────────────────────────────────────────────┴───┴─────────────────────────────────────┤
│  [F5] 複製     [F6] 移動     [Shift+F5] 原地建立副本     [F8 / ⌘⌫] 移至垃圾桶          │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 2. 核心檔案操作：複製、移動、新建與刪除

日常檔案處理絕大部分時間都在圍繞四項核心動作展開：複製、移動、新建目錄與清理刪除。

### 2.1 複製檔案與資料夾 (`F5` / `cm_Copy`)

複製操作的標準工作流：

1. **選中專案**：使用鍵盤方向鍵配合空格、或使用滑鼠在當前啟用面板中選中一個或多個檔案。
2. **按下 `F5`**（在 Mac 鍵盤上按 `Fn+F5`，或點選中間工具欄上的 **複製** 圖示）。
3. 彈出 **複製檔案 (Copy)** 對話方塊：
   - **目標路徑欄**：預設自動填入對側閒置面板當前的開啟路徑。你可以直接手動輸入修改，或在路徑末尾追加新的子目錄名實現“複製並自動歸檔”，也可以點選右側 `...` 按鈕瀏覽。
   - **開始 (`Enter`)**：立即在前臺啟動任務，並伴隨流暢的動態進度條。
   - **加入佇列 (`F2`)**：將本次傳輸派發給後臺非同步任務佇列執行（詳見 [7.4 節](#74-cm_operationspanel)）。
   - **高階選項 (Options)**：展開更高階的重名衝突策略、屬性保留規則與雜湊校驗選項。

```
┌────────────────────────────────────────────────────────┐
│ 複製檔案                                               │
│ 確認複製選中的 3 個檔案？                              │
│ 目標路徑: [/Volumes/Backup/Assets                    ] │
│ [高階選項 ▼]   [加入佇列 #1 ▾]   [取消]       [開始]   │
└────────────────────────────────────────────────────────┘
```

#### 在同目錄下快速製作備份副本 (`Shift+F5` / `cm_CopySamePanel`)
修改重要配置（例如 `nginx.conf`）前，往往需要先順手備份一份：

- 游標停留在該檔案上，按下 **`Shift+F5`**（`⇧F5`）。
- ATBCmder 會彈出複製視窗，但目標路徑依然停留在**當前面板自身目錄**，並貼心允許你直接指定新檔名（例如 `nginx.conf.bak`）。

#### 完美契合 macOS 系統剪貼簿 (`Cmd+C` ➔ `Cmd+V`)
ATBCmder 深度無縫打通了蘋果 macOS 的系統級剪貼簿體驗：

- **`Cmd+C` (`⌘C`)**：將選中檔案的絕對路徑複製到系統剪貼簿 (`cm_CopyToClipboard`)。
- **`Cmd+V` (`⌘V`)**：將剪貼簿中的檔案貼上複製到當前面板目錄 (`cm_PasteFromClipboard`)。
- **`Cmd+Option+V` (`⌥⌘V`)**：將剪貼簿中的檔案以“移動/剪下”形式貼上進來 (`cm_PasteAsMove`)。

---

### 2.2 移動與剪下檔案 (`F6` / `cm_Move`)

移動操作會將源路徑中的檔案提取並安全遷移到目標目錄中：

1. 選中待移動檔案，按下 **`F6`**（或 `Fn+F6` / 點選中間工具欄上的 **移動** 按鈕）。
2. 彈出 **移動檔案 (Move)** 對話方塊，確認目標路徑。
3. 按下 **`Enter`** 鍵立即執行：
   - **同分割槽移動 (Same-Filesystem Move)**：在 Mac APFS/HFS+ 分割槽內部移動時，系統僅僅修改檔案目錄樹指標，底層資料塊完全不重寫，哪怕移動 100 GB 檔案也是**毫秒級瞬間完成**。
   - **跨分割槽移動 (Cross-Filesystem Move)**：當目標在另一塊外接硬碟或 NAS 上時，系統會嚴謹執行流式讀寫、寫入校驗落盤，並在全部校驗完畢後才安全解鏈刪除原始檔（詳見第 9 章 3.5 節）。
4. 若目標路徑中已存在同名檔案，系統會自動暫停並撥出**衝突解決對話方塊**（詳見 [第 6 節](#6)）。

---

### 2.3 快速建立資料夾目錄 (`F7` / `cm_MkDir`)

需要在當前位置迅速搭建資料夾骨架：

1. 按下 **`F7`**（或 `Fn+F7` / macOS 快速鍵 `⇧⌘N` / `cm_MkDir`）。
2. 螢幕彈出簡潔明瞭的輕量級輸入框：`輸入新資料夾名稱:`。
3. 鍵入名稱後按下 `Enter` 確認。

```
┌──────────────────────────────────────────────┐
│ 新建資料夾                                   │
│ 輸入新資料夾名稱:                            │
│ [2026-09-Q3_財務報表                       ] │
│                      [取消]        [確定 (⏎)]│
└──────────────────────────────────────────────┘
```

#### 多層級連綴建立 (遞迴 mkdir -p)
你可以在一次輸入中建立深層巢狀結構。例如鍵入 `projects/2026/mobile/assets` 並按回車，ATBCmder 會像 UNIX `mkdir -p` 一樣瞬間連綴建立這四層資料夾。

#### 自動聚焦就位
新建完成後，面板游標會自動移動並精準停留在剛建立的新資料夾上，方便你立刻按 `Enter` 進目錄，或者按 `F5` 往裡面拷入檔案。

### 2.4 刪除檔案：安全廢紙簍 vs 物理永久抹除

在檔案管理中，安全與可恢復性重於一切。ATBCmder 提供了兩套清晰的刪除邏輯：

```
                  ┌────────────────────────────────────────┐
                  │            檔案刪除觸發途徑            │
                  └───────────────────┬────────────────────┘
                                      │
                 ┌────────────────────┴───────────────────┐
                 ▼                                        ▼
    [ F8 / Delete / Cmd+Backspace ]             [ Shift+Delete / Shift+F8 ]
                 │                                        │
                 ▼                                        ▼
      macOS 系統廢紙簍 (.Trash)                   物理永久解除連結 (Unlink)
      • 完全可撤銷可恢復                           • 繞過廢紙簍，不佔中轉空間
      • 訪達中支援“放回原處”                      • 磁碟空間立即可用
      • 各磁碟分割槽的 .Trashes 目錄                • 無專業資料恢復工具無法找回
```

#### 移至系統廢紙簍 (`F8` / `Delete` / `Cmd+Backspace`)
- 選中的檔案會呼叫系統底層的 `send2trash` 安全 API 移入廢紙簍。
- 如果發生誤刪，隨時可在Finder廢紙簍中右鍵選擇“放回原處”完好無損地復原。
- 確認彈窗的開啟或關閉可在偏好設定中自定義（`operations.confirm_delete`）。

#### 物理永久刪除 (`Shift+Delete` / `Shift+F8`)
- 徹底跳過廢紙簍，直接由作業系統解除檔案 Inode 索引，即刻釋放硬碟儲存空間。
- 特別適用於清理體積達數十 GB 的虛擬機器映象或臨時構建快取，避免擠佔廢紙簍空間或因空間不足導致刪除報錯。

#### 無廢紙簍卷宗智慧檢測預警 (`trash_unavailable`)
當你在某些非 Apple 原生格式的外接盤（如 FAT32、exFAT）或透過區域網掛載的 NAS 網路共享（SMB、SFTP、`vfs://`）上刪除檔案時，由於卷宗底層缺少 `.Trashes` 垃圾桶機制，macOS 無法將其移入廢紙簍。

此時，ATBCmder 會智慧攔截並彈出安全警示框：
```
┌────────────────────────────────────────────────────────┐
│ 廢紙簍不可用                                           │
│ 卷宗 '/Volumes/NAS/backup.iso' 不支援廢紙簍機制。      │
│ 您希望直接永久刪除此檔案嗎？                           │
│                                                        │
│ [✔] 對本次剩餘的所有專案應用相同操作                   │
│              [跳過]                     [永久刪除]     │
└────────────────────────────────────────────────────────┘
```
你可以從容選擇 **永久刪除**、**跳過**，或勾選 **對剩餘專案全部應用**，無需反覆彈窗打擾。

#### 多輪覆寫安全粉碎 (`Alt+Delete` / `cm_Wipe`)
對於包含敏感商業合同、私鑰憑據或機密資料的徹底銷燬：

- 選中目標，點選選單欄 **檔案 ➔ 粉碎檔案...**（快速鍵 `Alt+Delete` / `cm_Wipe`）。
- ATBCmder 會在解除檔案索引之前，使用偽隨機資料和全零對物理磁碟塊進行多輪覆寫，確保任何底層資料恢復工具都無法提取碎片。

## 3. 行內即時重新命名與名稱編輯

對單個檔案重新命名完全不需要開啟笨重的彈窗。ATBCmder 提供了靈動快捷的列表原地表格編輯模式。

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│  名稱                                  字尾     大小      修改時間              │
│  ▸ [..]                                         --:--     drwxr-xr-x            │
│  ● 2026年半年度財務分析報告            .pdf     4.2 MB    今天, 11:20           │
│    ▲                                                                            │
│    └── [行內可編輯文字框：主檔名自動高亮，.pdf 字尾處於保護狀態不被破壞]      │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 觸發方式
1. 將游標移動到目標檔案或資料夾上。
2. 按下 **`F2`** 或 **`Shift+F6`**（`cm_RenameOnly`），或用滑鼠對準已高亮的檔名輕點一下。
3. 當前單元格立刻轉變為可編輯的文字輸入框 (`QLineEdit`)。

### 智慧字尾保護機制 (Intelligent Extension Preservation)
以檔案 `2026年半年度財務分析報告.pdf` 為例：

- 進入行內改名狀態時，ATBCmder 會**自動僅僅選中前半部分主檔名**（`2026年半年度財務分析報告`）。
- 字尾名（`.pdf`）保持未選定狀態，徹底杜絕因誤刪副檔名導致 macOS 系統丟失檔案型別關聯的煩惱。
- 若確實需要修改字尾，使用方向鍵微調游標或按 `Cmd+A` 即可全選改動。

### 行內改名專屬快速鍵
- **`Enter` (`Return`)**：確認儲存新名稱，並即時更新檔案列表索引。
- **`Esc`**：放棄本次修改，瞬間恢復原檔名。
- **`Tab`**：提交當前修改，並**瞬間無縫開始下一行檔案的重新命名**！這項功能允許你像用 Excel 製表一樣，單手按 Tab 鍵行雲流水地順次對一整列檔案進行重新命名。

## 4. 進階檔案選擇與標記技術

在傳統檔案管理器中，游標移動與選中狀態是強繫結的——一旦不用滑鼠按住 `Cmd` 鍵單點，只要移動游標原有的選中就會丟失。而在 ATBCmder 中，**“游標瀏覽位置”**與**“已標記專案”**是徹底解耦獨立的，這賦予了高階使用者不可思議的多檔案篩選能力。

```
  狀態列呈現機制：
  [ ]  未選中狀態（游標所在行，但未被標記）
  [✔]  已標記選定狀態（匯入批次處理管道中）
```

### 4.1 全域性選擇動作

| 操作動作 | macOS 原生快速鍵 | 經典 Commander 鍵位 | 命令標識 (Command ID) | 功能說明 |
| :--- | :--- | :--- | :--- | :--- |
| **全部選定** | `Cmd+A` / `⌘A` | `Ctrl+A` / `Ctrl+Num+` | `cm_MarkMarkAll` | 標記當前面板內的所有檔案與子目錄 |
| **全部取消選定** | `Cmd+Shift+A` / `⇧⌘A` | `Ctrl+Shift+A` / `Ctrl+L` | `cm_MarkUnmarkAll` | 清空當前面板內所有已標記的高亮狀態 |
| **反向選擇 (反選)** | `Num*` / `⌥⌘I` | `Num*` (小鍵盤 `*`) | `cm_MarkInvert` | 反轉狀態：未選中的變為選中，已選中的變為未選中 |

---

### 4.2 萬用字元與規則批次標記

萬用字元標記功能讓你在包含成千上萬個檔案的龐大目錄中，僅憑兩三下擊鍵就能精準提取特定批次。

```
┌────────────────────────────────────────────────────────┐
│ 按萬用字元規則選擇檔案                                   │
│ 匹配規則: [*.jpg;*.png;*.webp                       ]  │
│                                                        │
│ [✔] 區分大小寫             [ ] 啟用正規表示式          │
│                      [取消]                  [確定 (⏎)]│
└────────────────────────────────────────────────────────┘
```

#### 批次選定群組 (`Num+` / `cm_MarkPlus`)
- 按下小鍵盤 **`+`** 號（或選單欄 **選擇 ➔ 選擇群組...**）。
- 輸入通用的 Shell 萬用字元規則：
  - `*.log`：選中所有以 `.log` 結尾的日誌檔案。
  - `*.jpg;*.png;*.webp`：使用分號分隔，一次性匹配多種格式圖片。
  - `data_2026_??.csv`：`?` 代表單個字元，精準匹配兩位月份檔案（`01` 至 `12`）。
  - `*草稿*`：匹配檔名中包含“草稿”字樣的任意檔案。
- 按回車鍵，面板中所有命中項瞬間全部標紅選中。

#### 反向剔除群組 (`Num-` / `cm_MarkMinus`)
- 按下小鍵盤 **`-`** 號。
- 輸入規則，從已經選中的大批檔案中反向剔除一部分（如輸入 `*test*` 剔除所有單元測試資料）。

#### 選中當前游標相同副檔名的所有檔案 (`Shift+Num+` / `cm_MarkCurrentExtension`)
- 游標移動到任意一個檔案上（如 `app.tsx`）。
- 按下 **`Shift+Num+`**。
- 當前目錄下所有的 `.tsx` 檔案瞬間全部被標記，無需手動鍵入文字。

### 4.3 範圍與單項標記

- **連續範圍框選 (`Shift+上 / Shift+下`)**：按住 `Shift` 鍵配合上下方向鍵移動，即可像文字編輯器框選文字一樣，向上或向下擴充套件連續的選擇區域。
- **單項勾選與步進 (`Space` / `Insert` / `cm_SelectOrDeselectFile`)**：
  - 遇到需要逐一核對的檔案，按一下 **空格鍵 (`Space`)** 即可勾選/取消勾選該條目；若游標處於資料夾上，按空格還會順帶計算出該資料夾的真實位元組大小。
  - 按 **`Insert`** 鍵（部分 Mac 鍵盤為 `Fn+Return`），系統會先標記當前條目，並**自動將游標向下移動一行**，讓你一指禪順暢完成逐行挑選。
- **觸控板與滑鼠配合**：
  - `Cmd + 點選`：在不影響其他選中項的前提下，獨立切換被點按行的勾選狀態。
  - `Shift + 點選`：以當前選區為錨點，將點選行之間整塊區域連續全選。

### 狀態列實時選中遙測

讓你在點選複製或刪除之前，對本次操作涉及的總檔案數和總位元組容量了然於胸。

## 6. 檔案重名衝突與覆蓋解決引擎

在日常管理中，遇到同名檔案覆蓋是最需要謹慎對待的環節。覆蓋了錯誤的版本往往會造成災難性的資料損失。ATBCmder 內建了企業級的重名衝突仲裁引擎，在真正寫入磁碟前全面核驗，並提供多維度的細粒度決策。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 確認檔案覆蓋 (Confirm File Overwrite)                                                  │
│                                                                                        │
│ 目標目錄中已存在同名檔案。                                                             │
│                                                                                        │
│ 原始檔:      /Users/brain/Downloads/build_artifacts.zip                                │
│ 原始檔資訊:  124,518,400 位元組, 2026-09-06 14:15                                        │
│                                                                                        │
│ 目標檔案:    /Volumes/Backup/build_artifacts.zip                                       │
│ 目標檔案資訊: 118,204,112 位元組, 2026-09-01 09:30                                       │
│                                                                                        │
│ 您希望如何處理？                                                                       │
│                                                                                        │
│ [全部跳過]   [全部覆蓋]   [手動更名]   [自動遞增更名]                                  │
│                                                                                        │
│ [取消]                                          [跳過]                 [覆蓋 (⏎)]      │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 覆蓋衝突對話方塊全面解析

當發生檔名重疊時，系統會暫停並彈出上述視窗：

1. **左右雙側後設資料對齊審查**：
   - 細緻到單位元組級別的檔案大小比對。
   - 修改日期與精確時間戳比對，系統會自動智慧高亮標明原始檔到底是“較新”、“較舊”還是“完全相同”。
2. **針對當前單項的處理按鈕**：
   - **覆蓋 (`Enter`)**：用原始檔寫入替換目標同名檔案。
   - **跳過 (Skip)**：保留目標現有檔案不動，繼續處理佇列中的下一個待辦檔案。
   - **取消 (`Esc`)**：立即中止後續的整個傳輸任務，已完成傳輸的檔案完整保留。
3. **批次與安全自動化策略**：
   - **全部覆蓋 (Overwrite All)**：靜默覆蓋本次任務中後續遇到的所有同名檔案，不再彈窗詢問。
   - **全部跳過 (Skip All)**：遇到同名檔案全部自動跳過。
   - **手動更名 (Rename)**：彈出一個輸入框，允許你為本次拷入的檔案臨時起一個新名字。
   - **自動遞增更名 (Auto-rename)**：系統自動在檔名後追加遞增數字字尾（如 `build_artifacts_1.zip`、`build_artifacts_2.zip`），確保新舊兩份版本並存，絕無丟失。

### 在複製視窗中預設衝突與校驗規則

對於大規模的備份或無人值守傳輸，你可以在發起複製（`F5`）時點選展開 **高階選項 (Options)**，預設全自動策略：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 複製高階選項配置面板                                                         │
│ ┌─ 衝突解決策略 ──────────────────────┐ ┌─ 屬性與校驗保障 ────────────────┐  │
│ │ 遇同名檔案時:    [彈窗詢問        ▾]│ │ [✔] 預先核驗目標盤剩餘空間        ││
│ │ 遇同名目錄時:    [遞迴合併        ▾]│ │ [✔] 保留修改日期與時間戳          ││
│ │ 屬性寫入失敗時:  [自動跳過        ▾]│ │ [✔] 保持原始屬性與 UNIX 許可權      ││
│ └─────────────────────────────────────┘ │ [ ] 強制清除只讀屬性              ││
│ ┌─ 過濾器 ────────────────────────────┐ │ [✔] 保持 POSIX 使用者與群組歸屬     ││
│ │ [ ] 忽略並排除空資料夾              │ │ [✔] 寫入後雜湊校驗: [SHA256     ▾]││
│ └─────────────────────────────────────┘ └───────────────────────────────────┘│
│ [將當前配置設為預設選項]                                                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **遇同名檔案時的策略 (When file exists)**：
  - `詢問 (Ask)`：遇到衝突立即彈窗由人工裁決（預設）。
  - `覆蓋 (Overwrite)`：直接覆蓋。
  - `跳過 (Skip)`：遇到同名直接跳過。
  - `覆蓋較舊檔案 (Overwrite older)`：僅當原始檔的修改時間比目標檔案更新時才覆蓋，非常適合單向增量同步。
  - `自動追加序號 (Rename copied)`：自動追加 `_1`, `_2` 字尾。
- **遇同名目錄時的策略 (When directory exists)**：
  - `遞迴合併 (Merge)`：將兩個資料夾的內容合併在一起，互不衝突的子檔案直接寫入。
- **高階屬性與完整性保障**：
  - **預先核驗剩餘空間 (Check free space)**：在開始寫入前，提前預先計算原始檔總體積，若目標盤容量不足，提前警告終止，防止拷到 99% 時發生磁碟寫滿故障。
  - **寫入後雜湊校驗 (Verify after copy)**：在將檔案寫入目標盤後，後臺實時計算源與目標的加密雜湊值（支援 `SHA-256`、`MD5`、`CRC32`），百分之百確保資料在傳輸過程中沒有受到靜默資料損壞（Bit-rot）。
  - **符號連結處理 (Follow links)**：決定是將符號連結作為快捷方式複製，還是將其背後的真實物理資料提取實體化。
  - **保留修改日期與所有權**：完整保持 POSIX 許可權標誌與檔案原始建立修改時間戳。

## 7. ⚡ 高手進階與底層技術深度剖析

雙面板工具之所以被高階工程師與系統管理員青睞，在於其底層直通 macOS 的 Darwin UNIX 核心。以下特性專門面向高階場景定製。

### 7.1 符號連結 (Symlink) 與硬連結 (Hardlink)

macOS 建立在 UNIX 之上，原生支援兩種截然不同的連結技術：

```
  符號連結 (Symbolic Link / 軟連結):
  [ 軟連結檔案 ] ──(路徑文字指標)──► [ 真實目標檔案或資料夾 ]
  • 可以跨越不同的物理硬碟驅動器與網路共享
  • 可以連結到資料夾目錄
  • 一旦目標原始檔被移走，軟連結即刻失效斷開

  硬連結 (Hard Link):
  [ 硬連結目錄項 A ] ──┐
                        ├──(直接指向相同的物理 Inode)──► [ 磁碟真實資料塊 ]
  [ 原始檔案目錄項 B ] ──┘
  • 無法跨越檔案系統分割槽（必須在同一個 APFS 容器內）
  • macOS 下只允許連結檔案，不允許連結資料夾
  • 資料始終安全，只有當指向該 Inode 的全部硬連結都被刪除時，真實資料才會被抹除
```

#### 建立符號連結 (`cm_SymLink`)
1. 在啟用面板選中一個或多個檔案或資料夾。
2. 選擇選單欄 **檔案 ➔ 建立符號連結...**（快速鍵 `cm_SymLink`）。
3. 系統會在對側目標面板建立指向所選原始檔絕對路徑的符號連結。
4. 面板列表中的屬性會清晰標出 `l` 標誌（如 `lrwxr-xr-x`）。

#### 建立硬連結 (`cm_HardLink`)
1. 在本地 APFS 分割槽上選中檔案。
2. 點選選單欄 **檔案 ➔ 建立硬連結...**（快速鍵 `cm_HardLink`）。
3. 系統會在對側面板生成一個共享相同 Inode 的全新目錄項。
4. 修改任何一側的內容，另一側實時同步反映；即便刪掉其中一份，另一份依然完好無損。

> [!NOTE]
> **連結邊界限制**：硬連結不能跨硬碟驅動器建立，也無法在網路共享掛載點（`vfs://`）上生成。若需要跨盤或跨網路對映，請始終使用**符號連結 (Symlink)**。

### 7.2 檔案屬性、時間戳與 UNIX 許可權 (`Alt+Enter` / `cm_SetFileProperties`)

透過屬性視窗直觀檢視與修改 POSIX 許可權：

```
┌────────────────────────────────────────────────────────┐
│ 檔案屬性 - production_api.py                           │
│ ┌─ 後設資料資訊 ───────────────────────────────────────┐ │
│ │ 絕對路徑:     /Users/brain/work/production_api.py  │ │
│ │ 檔案大小:     84,210 位元組                          │ │
│ │ 建立時間:     2026-03-12 10:14:22                  │ │
│ │ 修改時間:     2026-09-06 13:45:01                  │ │
│ │ 訪問時間:     2026-09-06 15:30:10                  │ │
│ └────────────────────────────────────────────────────┘ │
│ ┌─ UNIX 許可權控制 (chmod) ────────────────────────────┐ │
│ │ 八進位制模式碼: [ 755 ]                              │ │
│ │ ┌─ 所有者 ─┐   ┌─ 群組 ───┐   ┌─ 其他人 ─┐         │ │
│ │ │ [✔] 讀取 │   │ [✔] 讀取 │   │ [✔] 讀取 │         │ │
│ │ │ [✔] 寫入 │   │ [ ] 寫入 │   │ [ ] 寫入 │         │ │
│ │ │ [✔] 執行 │   │ [✔] 執行 │   │ [✔] 執行 │         │ │
│ │ └──────────┘   └──────────┘   └──────────┘         │ │
│ └────────────────────────────────────────────────────┘ │
│                             [取消]         [確定 (⏎)]  │
└────────────────────────────────────────────────────────┘
```

1. **調出方式**：選中任意條目按下 **`Alt+Enter`**（`⌥⏎` / `cm_SetFileProperties`）。
2. **後設資料概覽**：檢視精確到單位元組的檔案大小、建立時間 (`btime`)、修改時間 (`mtime`) 與訪問時間 (`atime`)。
3. **UNIX 許可權矩陣**：
   - **互動勾選框**：為 **所有者 (Owner)**、**群組 (Group)** 和 **其他人 (Others)** 獨立配置讀取 (`r`)、寫入 (`w`) 與執行 (`x`) 許可權。
   - **雙向八進位制聯動**：直接在八進位制輸入框鍵入數值（如執行程式輸入 `755`、普通文件輸入 `644`、機密 SSH 私鑰輸入 `600`），核取方塊會瞬間實時聯動變換，反之亦然。
4. 點選 **確定 (`Enter`)**，系統透過底層的 POSIX `chmod` 即刻完成許可權賦予。

### 7.3 資料夾容量實時統計 (`cm_CountDirContent` / `cm_CalculateSpace` / `Space`)

出於檔案系統效能保護考慮，所有檔案管理器在開啟目錄時預設只會將資料夾的大小顯示為 `<DIR>` 或 `--`，因為遞迴遍歷百萬檔案的子樹會極大地拖慢列表速度。ATBCmder 提供了按需極速統計：

- **統計單個資料夾大小 (`Space` / `Insert` / `cm_SelectOrDeselectFile`)**：把游標停在任意資料夾上按一下 **空格鍵 (`Space`)**，系統會在後臺子執行緒極速統計並將其體積替換顯示在列表中（如 `14.2 GB`）。
- **統計面板內所有資料夾大小 (`Alt+Shift+Enter` / `⌥⇧⏎` / `cm_CountDirContent`)**：
  - 一鍵遍歷當前面板中所有的可見資料夾。
  - 自動更新每一行目錄的具體位元組總量。
- **統計選中資料夾累計大小 (`Ctrl+L` / `⌃L` / `cm_CalculateSpace`)**：
  - 彙總所選目錄的位元組總量，並在底部狀態列彙總累計的檔案總數、目錄總數與總容量佔用。

### 7.4 後臺三通道操作佇列 (`cm_OperationsPanel`)

在傳統檔案管理器中，複製一個 50 GB 的素材庫往往意味著當前視窗被死死鎖住。ATBCmder 採用了業界領先的 **3 通道非同步多工佇列架構**。

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ 後臺任務監控器 (Background Operations)                                                 │
│ ┌─ [佇列 #1 (執行中)] ────────────┬─ [佇列 #2 (空閒)] ────┬─ [佇列 #3 (空閒)] ───────┐ │
│ │                                                                                    │ │
│ │ [傳輸中] 複製: 14 項 -> /Volumes/BackupDrive/Media                                 │ │
│ │   當前正在寫入: RED_4K_Clip_0042.r3d (2.4 GB / 8.6 GB)                             │ │
│ │   實時速率: 428.5 MB/s | 預估剩餘時間: 00:01:14                                    │ │
│ │   [████████████████████████████████░░░░░░░░░░░░░░░░░░] 64%                         │ │
│ │                                                                                    │ │
│ │ [已排隊] 移動: 4 項 -> /Volumes/BackupDrive/RAW_Audio                              │ │
│ │ [已完成] 複製: 28 項 -> /Users/brain/Projects/Website                              │ │
│ │                                                                                    │ │
│ └────────────────────────────────────────────────────────────────────────────────────┘ │
│                                         [終止當前任務]  [清空已完成]        [關閉]     │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

#### 為什麼設計三條獨立佇列？
- **單佇列內部嚴格序列化 (FIFO)**：在 **佇列 #1** 內部的任務會一件接一件順序執行。對於機械硬碟或同一張儲存卡，序列讀取能徹底避免磁頭反覆來回尋道或 I/O 爭搶，反而能夠以最大吞吐量完成。
- **跨佇列之間高度並行併發**：**佇列 #1**、**佇列 #2** 和 **佇列 #3** 各自在獨立的後臺執行緒中併發運轉。你可以把針對 **內建 NVMe 固態硬碟** 的任務分給佇列 1，把往 **外接行動硬碟** 傳輸的任務分給佇列 2，把往 **網路 NAS** 上傳的任務分給佇列 3——徹底跑滿不同物理通道的匯流排頻寬！

#### 如何將任務加入後臺佇列？
1. 選中檔案按 `F5`（複製）或 `F6`（移動）。
2. 在彈出對話方塊中不要按開始，而是點選 **加入佇列 #1**（或點選下拉箭頭選擇 **佇列 #2**、**佇列 #3**）。
3. 對話方塊隨即關閉，主介面絲滑響應，你可以立即繼續翻閱檔案或處理其他工作。

#### 管理後臺佇列視窗 (`cm_OperationsPanel`)
- 點選主工具欄上的 **⚡ 佇列** 按鈕，或在選單欄選擇 **命令 ➔ 後臺任務管理**（`cm_OperationsPanel`）。
- **實時遙測指標**：清晰檢視當前正在活躍傳輸的檔名、瞬時吞吐速率（如 `428.5 MB/s`）與動態 ETA 倒計時。
- **狀態色彩標籤**：
  - `[已排隊]`：正在等待前面的任務處理完畢。
  - `[傳輸中]`：資料塊流式寫入中。
  - `[已完成]`：任務全部成功，位元組校驗無誤。
  - `[失敗]`：遭遇 I/O 錯誤（點選可檢視詳細錯誤日誌）。
  - `[已取消]`：使用者手動中止。
- **任務調控操作**：支援隨時 **暫停/恢復**、**終止特定任務** 與 **清空已完成記錄**。
- **後臺衝突通知**：若後臺佇列在執行過程中遭遇重名衝突，系統會貼心發出通知橫幅，點選即可處理，不會阻塞其他併發佇列的運轉。

## 8. 步驟化實用實戰流程

### 實戰 1：帶校驗的跨驅動器安全備份

**場景目標**：將 Mac 本地一份珍貴的照片庫備份至外接 APFS 移動固態硬碟，要求 100% 防靜默損壞，遇到重名時自動遞增編號。

```
第 1 步：在左面板開啟源目錄 (~/Pictures/2026_照片素材)。
第 2 步：在右面板開啟外部備份目標盤 (/Volumes/SanDiskPro/Photo_Backup)。
第 3 步：在左面板按下 Cmd+A (全選)。
第 4 步：按下 F5 (複製)。
第 5 步：點選 [高階選項 ▼] 展開高階引數配置：
         • 將“遇同名檔案時”設定為: [自動遞增更名]
         • 勾選 [✔] 寫入後雜湊校驗: 選擇 [SHA-256]
         • 勾選 [✔] 保留修改日期與時間戳
         • 勾選 [✔] 預先核驗目標盤剩餘空間
第 6 步：點選 [開始]。
```
*執行結果：ATBCmder 在資料落盤後即時比對 SHA-256 雜湊值，確保寫入外接盤的每一位元都完好無損，遇到同名快照自動加上 `_1` 字尾，全程無需人工干預。*

---

### 實戰 2：萬用字元定向篩選與軟連結部署

**場景目標**：在一個包含源工程與編譯產物的混合目錄中，精準選定所有的 JavaScript、TypeScript 與 JSON 檔案（排除所有測試檔案與 `.log`），並將其軟連結批次釋出到測試沙盒中。

```
第 1 步：左面板定位到工程原始碼目錄: /Users/brain/dev/app/src。
第 2 步：右面板定位到測試環境庫目錄: /Users/brain/dev/testbed/lib。
第 3 步：按下小鍵盤 Num+ (選擇群組)。
第 4 步：輸入規則: *.ts;*.tsx;*.js;*.json 並按回車。
第 5 步：發現把 *.test.ts 單元測試檔案也帶進來了，按下小鍵盤 Num- (反向剔除)。
第 6 步：輸入規則: *.test.ts 並按回車。
第 7 步：觀察狀態列：精準選中 84 個核心程式碼檔案。
第 8 步：選擇選單欄 檔案 ➔ 建立符號連結... (cm_SymLink)。
```
*執行結果：84 個符號連結瞬間在測試目錄生成，全部精準指向左側原始檔，開發除錯隨時生效。*

### 實戰 3：利用後臺雙通道並行匯入高速相機卡

**場景目標**：從兩張插在雙讀卡器上的高速攝影卡中，同時將數十 GB 影片和音訊素材拷入工作站 RAID 陣列，期間不卡頓介面。

```
第 1 步：左面板開啟 A 卡 (/Volumes/CFexpress_A)。
第 2 步：Cmd+A 全選原始素材，按下 F5。
第 3 步：點選 [加入佇列 #1]，後臺即刻開始高速拉取。
第 4 步：在左面板按 Cmd+T 新建一個標籤頁，開啟 B 卡 (/Volumes/SD_Card_B)。
第 5 步：Cmd+A 全選獨立音軌錄音，按下 F5。
第 6 步：點選佇列下拉箭頭，選擇 [加入佇列 #2]。
第 7 步：點選工具欄 ⚡ 圖示 (cm_OperationsPanel) 展開監控。
```
*執行結果：兩張卡分別在獨立的資料佇列中以硬體匯流排極限速度並行吞吐，主介面依舊清爽順暢，你可以繼續檢視照片或編寫日誌。*

## 9. 安全與系統重要警示

> [!WARNING]
> **外接磁碟與網路共享上的直接永久刪除風險**：
> 格式化為 FAT32、exFAT 或 NTFS 的外接儲存裝置，以及透過區域網連線的 SMB/SFTP 共享路徑，通常不支援蘋果系統的 `.Trashes` 廢紙簍機制。在這些位置刪除檔案時，系統會提示廢紙簍不可用，點選確認將導致檔案**被物理直接永久刪除**。操作前請務必仔細確認路徑欄。

> [!CAUTION]
> **批次覆蓋模式下的不可逆覆蓋**：
> 在衝突彈窗中點選 **全部覆蓋 (Overwrite All)** 後，後續遭遇的所有同名檔案都將被無條件靜默覆寫。如果源目錄中存在意外重名的檔案，現有的同名備份將被不可逆地覆蓋掉。在無人值守的批次複製中，建議優先選擇 **自動遞增更名** 或 **覆蓋較舊檔案**。

> [!IMPORTANT]
> **APFS 硬連結跨卷限制**：
> 硬連結絕對無法跨越不同的物理分割槽、APFS 卷宗容器或 DMG 映象。如果嘗試在 `/Users/...` 與外接硬碟 `/Volumes/ExternalDrive/...` 之間建立硬連結，操作必然會報錯失敗。凡是跨卷或跨網路對映，請一律使用 **符號連結 (Symlink)**。

> [!TIP]
> **最佳化 NVMe 高速固態硬碟的寫入吞吐**：
> ATBCmder 針對 Apple Silicon 統一記憶體架構與超高速 NVMe SSD 進行了深度最佳化。預設情況下，檔案操作採用大容量的 **1 MB 讀寫緩衝區** (`operations.copy_buffer_size`)。如果你的工作流涉及萬兆網路環境或超高速磁碟陣列，可在 **偏好設定 ➔ 檔案操作** 中進一步調優緩衝區大小以榨乾匯流排極限。
